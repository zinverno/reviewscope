# PR-04. Контракт эмбеддингов ReviewScope

## Идентичность

Ключ DuckDB и сессии — `(review_id, sha256(text_or_empty().encode("utf-8")), encoding_id)`. В исторической колонке `model_name` новые записи хранят `rs-embedding-v2:` и SHA-256 компактного JSON от полей `EncodingContract` с сортировкой ключей. Человекочитаемое имя по-прежнему доступно через `provider.name`.

| Поле | Что оно фиксирует для штатного провайдера |
|---|---|
| Модель и revision | Hub-репозиторий `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` и commit `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`. В этом snapshot находятся веса, tokenizer, правила токенизации и конфигурация mean pooling. Для другой модели нужен её собственный полный SHA. |
| Режим encoder | `SentenceTransformer.encode`, без prompt, выход `sentence_embedding`, Torch CPU, float32. Нормализация выходов выключена. |
| Форма и усечение | 384 компоненты, максимум 128 токенов с учётом специальных токенов, batch size 64. Раньше конфигурация указывала 512, но модель использовала свой предел 128. При первой загрузке сверяются выходная размерность и допустимый предел модели и tokenizer. Затем провайдер явно устанавливает контрактную длину. Несовпадение размерности или превышение предела прерывает расчёт. |
| Реализация | В идентификатор входят версии дистрибутивов sentence-transformers, transformers, tokenizers и torch. Для их чтения достаточно метаданных пакетов. Версии численных библиотек и CPU-инструкции могут давать небольшие отличия при повторном вычислении на другой машине. |

Версия v2 передаёт непустой текст целиком, включая регистр, Unicode и пробелы. Усечение выполняет tokenizer после формирования ключа. При одинаковом префиксе два длинных текста могут получить одинаковые векторы с разными ключами. Для `None` и пустой строки входом служит `""`. Любой пробельный вход получает нулевой вектор без вызова модели. Исторический `NormalizedReview.fingerprint()` сохраняет прежнюю семантику для потребителей этого API.

Для чтения готовых векторов веса не нужны. На хосте без optional-пакетов штатный v2-провайдер запрашивает явно заданный профиль `REFERENCE_RUNTIME`. Для векторов, подготовленных другим стеком, читатель может передать `SentenceTransformerProvider(runtime=...)` с профилем сборщика. На промахе провайдер сверяет запрошенный профиль с установленным. Для нового выпуска демо нужно проверить чтение его контракта и на лёгком хосте.

## Хранение и ошибки

- Порядок входа и повторы сохраняются в выходной матрице `(n, dim)` типа float32. На промахе один уникальный ключ обрабатывается один раз. Чтение DuckDB идёт пакетами до 256 ключей, или 768 параметров SQL.
- Сохранённый вектор неправильной формы, NaN, Inf или ненулевой вектор для пробельного текста считается промахом. Writable-база получает проверенную замену по тому же ключу. В обычном локальном read-only режиме замена остаётся в памяти. Ошибка encoder останавливает весь новый батч до его публикации.
- Публичный preflight проверяет содержимое векторов. При недостающей или повреждённой строке публичный режим останавливается до загрузки encoder. Данные «похожей» модели и старые строки по одному лишь имени не используются. Обычные writable-базы могут содержать обе версии рядом, автоматического удаления старых строк нет.

## Упакованное демо

Манифест фиксирует SHA-256 файла `85ca0756ca60f56c735360ab46632d8893287635e7fec1a28548f97dae5fcfe2`. Исторические revision и версии библиотек в нём отсутствуют. Поэтому штатное read-only открытие принятого набора выбирает отдельное пространство `rs-frozen-demo:`. Явно переданный провайдер всегда запрашивает собственный контракт.

Для допуска нужны 1 058 отзывов и 1 058 векторов исходной модели с размерностью 384. Из **открытого соединения** читаются строки в порядке `review_id, text_hash`. Для каждой строки в общий SHA-256 добавляются 32 байта SHA-256 от компактного UTF-8 JSON-массива `[review_id, text, text_hash]` и байты вектора little-endian float32. Ожидаемый итог — `b04e06b7cae1d945cb5b898ef9a969f4349cec092f9ee6b70ea18fa979e2385b`. Результаты выдаются только по точному тексту из этого набора. Изменение текста или вектора в БД лишает набор допуска, даже если исторический ключ ещё совпадает. Полную целостность файла независимо проверяет `python scripts/build_public_demo_dataset.py --verify`.

## При смене модели

Для оценки поиска конкретной проблемы используйте [офлайн-бенчмарк кандидатов PR-05](embedding-benchmark.md).

Обновите revision и проверяемые параметры контракта. Для изменения правил подготовки входа измените версию ключа. Для изменений адаптера кодирования измените идентификатор режима. Новые векторы записывайте отдельно и проверьте результаты и пороги cosine на фиксированных парах с независимой разметкой перед переносом порогов. Для базы валидации со старым штампом используйте новый путь. Утверждённый демо-артефакт обновляется отдельно.

## Проверка на синтетике

Один локальный запуск MiniLM на CPU, Python 3.14.7, DuckDB 1.5.5, стек `REFERENCE_RUNTIME`. Веса уже были на диске, `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`. Вход — восемь отзывов `r00001`–`r00008` из проверенного демо в порядке ID. Замер охватывает `embed_reviews`; открытие соединения и предварительный подсчёт попаданий вынесены за таймер.

| Состояние | Попаданий до вызова | Вызовов encoder за замер | Время |
|---|---:|---:|---:|
| Пустая временная DuckDB, включая загрузку модели и запись | 0/8 | 1 | 19 843,502 мс |
| Та же сессия | 8/8 | 0 | 0,041 мс |
| Новое read-only соединение и новый провайдер | 8/8 | 0 | 2,949 мс |

Три матрицы `(8, 384)` float32 совпали побитно. Между новым расчётом и архивом максимальная разница компоненты составила `1,49 × 10⁻⁷`, минимальный cosine соответствующих строк — `0,99999988`. Ни одна из 28 пар не достигла порога 0,88 в обоих вариантах. Проверка длинного входа подтвердила усечение хвоста на штатном пределе. Время зависит от нагрузки этой машины, а эта выборка не оценивает качество поиска или порог на клиентском корпусе.
