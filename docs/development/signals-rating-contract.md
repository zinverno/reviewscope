## Результат и область

Порт 8000 сохраняет отдельный read-only API `/api/v1/places/{place_id}/analysis` и `/reviews` той же точки. У публичного кабинета свой producer `public-explainable-signals-v1`. Он открывает DuckDB read-only, сверяет SHA-256 и идентичность frozen encoding, читает только готовые векторы. В manifest перечислены все 12 точек, result digest каждой и SHA-256 полных JSON-байтов. Входной SHA-256 равен `85ca0756ca60f56c735360ab46632d8893287635e7fec1a28548f97dae5fcfe2`. Исторический набор векторов имеет отдельный encoding ID. Ревизия исходной модели неизвестна. [Манифест](../../prototypes/reviewscope-ui/src/demo-signals/manifest.json) · [Полный пример p1](../../prototypes/reviewscope-ui/src/demo-signals/p1.json)

Порядок точек и review ID лексикографический. Окна включают обе границы. Состав окна связывается с точными версиями в массиве reviews. При равной доле лидирующей оценки выбирается меньшая звезда. Версия публичного отзыва совпадает с PR-15–16 и связывает SHA набора, точку, review ID, дату, текст и оценку. Манифест метода внутри результата содержит эффективные конфигурации и порядок округления. Все JSON конечны.

В локальном TLS-сервисе 8001 старые `POST /api/v1/workspaces/{w}/runs` с `snapshot_integrity_and_summary_v1` и `GET .../snapshots/{s}/summary-metrics` сохраняют свои результаты. Новый kind `snapshot_explainable_signals_v1`, engine `1`, definition `signals-1`, model `unused` использует ту же очередь и отдельный ключ запроса. Успех означает публикацию артефакта `snapshot-explainable-signals-1`. Записи берутся из `job_versions` и сверяются с байтами поколения, реестром, квитанцией, отпечатками входов и manifest. Сортировка по version UUID. При смене автора, внешнего ID, поставки или точки объединение по тексту исключено. Идентичная ранее принятая версия может законно состоять в двух снимках.

`GET /api/v1/workspaces/{w}/snapshots/{s}/signals?source_id={source}` проверяет допуск и перечисляет запуски. С `run_id` возвращается ограниченная проекция проверенного результата, включая SHA полных байтов. Для чтения исходной версии служит `.../reviews/{version}`. Для проверки контракта OpenAPI откройте `https://127.0.0.1:8001/openapi.json` на одноразовом стенде. В кабинете список запусков и выбор точки доступны в разделе снимка.

## ADR · дата оценки и доступность

Для публичного freeze выбрана **2026-11-24**, дата задания. Новый вызов `AnalysisEngine.analyze(..., as_of=..., explain=True)` раскрывает значения из того же пути, которым рассчитаны веса. Прежний default использует календарную дату системы. Каноническая заявка получает дату из неизменяемого `analysis_run.created_at` при постановке, в UTC. Получение поставки не заменяет время публикации отзыва. Первые канонические метрики не зависят от давности. Semantic SHA исключает изменяемый между заявками run UUID, включает дату, workspace, source, batch, snapshot, версионный состав и эффективный метод. SHA артефакта также охватывает run UUID и завершающий LF.

Канонический worker группирует записи по точке внутри единственного снимка. N eligible и N total у каждого показателя относятся к этой точке. Неполный охват исключает достоверное заполнение календарных пропусков нулями. Для пустого знаменателя возвращается null и причина. Модель на отсутствующих входах не запускается. Выборка, версия и исходный текст доступны исключительно через действующий допуск.

## Вычисления

- База объёма — медиана предыдущих календарных дней. Модифицированный z равен `0.6745 × (observed − median) / max(MAD, 1)`. При median < 1 обычный множитель отсутствует. Наблюдаемое число за день хранится отдельно от числа записей в окне рейтингового события.
- Рейтинговый детектор сравнивает распределения среди оценённых записей в каждом окне. Используется JSD с натуральным логарифмом, диапазон до ln 2, epsilon и округление исходного детектора. Обе границы, число исключённых, доминирующая категория и её изменение доступны в результате.
- Координация использует взвешенную сумму семи прежних нормализованных компонент, умноженную на 100. В артефакте есть точные входы, веса, отображаемые детали и контрсигналы. Отдельный построчный индекс координации лежит в 0–1.
- Для веса `quality = .35 specificity + .20 category + .25 relevance + .20 recency`, входы нормализованы до 0–1. Давность равна `0.5 ** (max(0, days_old) / 365)`. Из построчного индекса координации вычитается `round(.30 × max(dup, tpl), 3)`. Остаток округляется до трёх знаков и ограничивается снизу нулём.
- `penalty = .30 dup + .25 tpl + .20 residual`. Итог равен `round(clamp(1 + 2 × max(0, quality − .50) − penalty, .25, 2), 4)`. Промежуточные значения в trace предшествуют округлению UI.
- Исходное среднее равно `sum(r)/n`, модельное — `sum(w×r)/sum(w)`. Для записи вклад равен `w×r/sum(w)`. Знак изменения в PR-17 — weighted минус raw. Совместимое старое поле details.delta использует противоположное направление. Фильтр оценки или состава окна отбирает ID из всего результата до пагинации. Веса и исходный baseline сохраняются. Для детекторов под фильтром показывается `FILTER_NOT_COMPUTED`. Официальный рейтинг площадки неизвестен.

## Термины

В просмотренных моделях, HTTP-схемах, сериализациях, экранах и документации нет калиброванной вероятности или доверительного интервала. Совместимые `*_probability`, `coordinated_review_probabilities` и `review_probability_components` в scoring/config обозначают шкалу эвристических признаков. `ScoreResult.confidence`, `ComponentScore.confidence`, старые API/табличные поля confidence и бейджи Streamlit — категориальные уровни правил. Названия synthetic-like/templated в прежней методике описывают текстовый паттерн. Термины fraud, manipulation, fake, AI и bot в исторических пояснениях, тестах и ограничениях не задают метку истины для записи. Новая выдача использует `heuristic_score`, `evidence_band` и `severity`. Значение 0.65 не даёт оценки вероятности нарушения. По истории автора нельзя установить адрес, работу или поездки.

### Локальный профиль ресурсов

Публичный процесс использовал CPU, замороженные векторы, один поток DuckDB, OPENBLAS_NUM_THREADS=1 и OMP_NUM_THREADS=1. Первый расчёт 1 058 из 1 058 записей занял 16,68 с с Linux ru_maxrss 325 364 КиБ. Повтор в том же процессе занял 18,95 с с накопленным максимумом 328 028 КиБ. Первая отдельная сборка дала 16,43 с. PostgreSQL в публичном расчёте не участвует.

На одноразовом PostgreSQL 18.6 один запуск worker на A занял 2,09 с, повтор в новом процессе 1,61 с. Пики worker/backend на публикации составили 211 112/33 696 и 213 136/33 488 КиБ. Для B значения составили 1,58 и 1,70 с, 211 416/33 488 и 211 156/33 488 КиБ. Оба набора полностью оценены по исходным звёздам и тексту, у всех 3 и 6 записей автор отсутствует. Эти измерения включают запуск процесса и прогрев библиотек на одной машине.

Вход ограничен 4 МиБ и 10 000 позициями, чтение версий идёт страницами по 64. Версия 1 сохраняет предел одного опубликованного JSON в 65 536 байт. При превышении возвращается RESOURCE_LIMIT с числом проверенных записей и без частичного результата. SQL worker использует statement_timeout 10 с, lease 15 с с продлением. Это локальные измерения, производственный throughput и физический телефон не проверялись.
