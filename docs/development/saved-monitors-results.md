# PR-26 · Результат проверки контракта

**NEEDS_MONITOR_CONTRACT_REVIEW · MONITOR_INCREMENTAL_PROFILE_BLOCKED.** Повторный импорт и запуск PR-22 требуют согласования порядка блокировок на принятой 0020. Draft содержит контракт, запрос сравнения двух снимков, воспроизводимую проверку зависимости и эксперимент с настоящим worker. Кабинет ещё не предоставляет сохранённые мониторы.

## Где расходится порядок

На PostgreSQL 18.6 штатный операторский импорт B дошёл до ожидания workspace, уже удерживая UPDATE на source. Штатный enqueue PR-22 начал с UPDATE на workspace и затем требует SHARE на source в candidate_scope. Для наблюдения обеих транзакций тест задерживает только membership инициатора PR-22. У импортёра отдельный актор. Наблюдатель подтверждает очереди с помощью pg_blocking_pids, затем получает 55P03 при пробе KEY SHARE NOWAIT на точном source. Тест отменяет свой импорт до снятия барьера. Решение получает 202. Цикл и тайм-аут намеренно не создаются. Проверка порядка завершается с exit 1.

| Путь | Участок кода |
|---|---|
| Регистрация поставки оператором | `operational/import_delivery.py::authorize`, совместное получение `FOR UPDATE OF s FOR SHARE OF a,w,m,p` |
| Enqueue PR-22 | `0016_aspect_decisions.sql::enqueue_decision` вызывает `0005_background_jobs.sql::job_writer` до `0012_candidate_search.sql::candidate_scope` |
| Browser importer | Отдельная точка входа `0007_browser_delivery.sql::browser_claim`. Наблюдение на операторском импорте не доказывает фактический порядок этого плана. |

Исходное дерево #29 содержит оба пути. Исправление 0020 относится к подтверждению темы с созданием аспекта. До решения о совместном порядке импортёра и writer запись мониторов и публикация reuse в сервисе закрыты. Для устранения блокера требуется исследовать обе точки импорта и сохранить полномочия операторов, ledger и независимость workspace.
