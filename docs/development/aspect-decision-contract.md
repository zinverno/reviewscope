# PR-22 · Решение о жалобе в полном снимке

**Экспериментальный режим с ручной проверкой.** Для конкретной версии определения можно запустить локальную оценку всех пригодных версий отзывов. Результат описывает высказывания в поставке. Независимых меток реальных клиентов нет. На отложенной синтетике все три метода пропустили часть жалоб. Лексический контроль, доступный в кабинете, нашёл 4 из 32 жалоб с известной полярностью, включая 0 из 6 жалоб на очередь до заказа. Нулевой машинный счётчик совместим с пропущенными жалобами. [Протокол](../../tests/data/fixtures/decision_protocol_v1.json) · [Сравнение и ошибки](aspect-decision-results.md)

## Область решения

Путь задания проходит через workspace, проект, source, immutable snapshot и run. У строки решения есть UUID исходной **версии** отзыва. У определения есть проектные aspect_id, version_id, SHA PR-20, origin и сохранённые имя, описание, включающие и исключающие примеры. Историческая выдача сохраняет версию, выбранную при запуске. Архивирование закрывает новые заявки. Новая редакция требует явного запуска. Один и тот же текст с разными принятыми идентичностями даёт отдельные строки. Номер кластера, рейтинг, дата, автор и поисковый запрос в классификации не участвуют.

Пригодный текст содержит хотя бы один символ после Python `str.strip()`. SQL использует тот же перечень пробельных кодовых точек. Учитываются все принятые члены снимка. Пустые строки получают `excluded_blank`. Для каждого пригодного отзыва и одного аспекта сохраняется одно решение. Поиск PR-19 и rerank PR-21 сохраняют собственные API, артефакты и входные пулы. [Определения PR-20](aspect-definition-contract.md)

| Outcome | Как считать |
|---|---|
| complaint, mixed | Упомянут точный аспект и модель выделила явную претензию. Mixed означает сочетание позиций об одном аспекте. |
| denial, positive, neutral | Упомянут аспект. Есть отрицание проблемы, положительная или нейтральная позиция соответственно. |
| unclear | Модель распознала тему, позиция осталась неясной. |
| not_mentioned | Модель сочла аспект отсутствующим. |
| topic_uncertain | По тексту модель не определила, обсуждается ли этот аспект. |

Отсутствие вычисления имеет своё состояние. Неподдерживаемую редакцию кабинет показывает до запуска. Отсутствие или несовпадение локальных весов, недействительный профиль, отзыв допуска, отмена и ресурсный отказ оставляют итоговую сводку пустой. Пользователь видит последний зафиксированный прогресс. Выполненное машинное воздержание входит в число обработанных.

## Профиль и основания

В кабинете доступен контроль `aspect-linear-lexical-v1`, пороги `calibrated-v1`. Для семантики поддерживаются шесть точных payload c ручным origin. Их можно сохранить через обычную форму PR-20. Проверяются все поля байтово значимых строк, включая порядок примеров. Поддержка произвольных определений не установлена. [Шесть точных шаблонов](../../src/reviewscope/resources/decision-definitions.json)

Для каждого шаблона обучена собственная многоклассовая линейная голова на символьных n-граммах. Веса числовые, NPZ с `allow_pickle=False`. До вычисления проверяются размер, SHA, форма, конечность коэффициентов и выбранный порог. Идентичность профиля включает имя, версию признаков и агрегации, хэши определений и весов и набор порогов. SQL привязывает её к run, worker сверяет с загруженной реализацией. Опубликованный manifest дополнительно сохраняет фактические версии Python, NumPy и scikit-learn и dtype float64. Score — разность двух старших логитов. Оценка вероятности не калибровалась. У двух исследовательских вариантов токенизацию и кодирование выполняет локальная фиксированная ревизия MiniLM. Весов Transformer для кабинетного лексического контроля не требуется. [Реализация](../../src/reviewscope/aspect_decisions.py) · [Выбор до открытия test](aspect-decision-evidence/selection.json)

Окна длиной до 160 исходных кодовых точек с шагом 112 покрывают текст до конца. Для трансформера слишком длинное окно делится по фактической токенизации пары. Если предсказана жалоба, сохраняется соответствующее окно. Отдельную положительную позицию или отрицание в непересекающемся окне можно сохранить вторым контекстом. Строка решения содержит SHA версии и текста и полуинтервалы `[start,end)` в исходном Unicode. Номера смещений переживают CRLF, emoji и комбинируемые знаки. Результат `not_mentioned` не получает основание жалобы. Кабинет отделяет окна модели от точной лингвистической границы жалобы. При открытии он сверяет источник, версию, SHA оригинального текста, границы и контрольную сумму manifest.

## Запуск, публикация и чтение

Миграция `0016_aspect_decisions` добавляет `decision_binding` и `decision_row`. Задание `snapshot_aspect_decision_v1` отделено от поиска и rerank. Артефакт `aspect-decision-1` содержит сводку и SHA отсортированного множества строк. Сами строки хранятся в PostgreSQL, без копии исходного текста. Хэш строки охватывает UUID версии, оба SHA исходника, исход, основные и встречные границы, оценку и код основания. Хэш всего результата учитывает каждую строку в порядке UUID. [Миграция](../../operational/migrations/versions/0016_aspect_decisions.sql)

1. В кабинете выбрать снимок, источник и сохранённую редакцию аспекта. Явный POST на `/api/v1/workspaces/{w}/snapshots/{s}/decisions` передаёт source_id, aspect_id, version_id, профиль и UUID команды. Повтор с тем же ключом, субъектом и входом возвращает исходную задачу. При потере сетевого ответа используется тот же ключ.
2. Worker проверяет заявителя, сессию, текущую роль, удостоверение хранилища, разрешение на конкретные байты источника, происхождение синтетического проекта, исходные файлы, SHA проекции и членство. Оператор должен явно включить `decision_allowed` для конкретной строки `browser_admission` вместе с разрешениями на evidence и candidates. При миграции новое разрешение выключено.
3. До инференса сверяется исходная поставка. Один дочерний CPU-процесс получает данные через анонимный канал и пишет ответы партиями до 32 строк. В его окружении отсутствуют учётные данные БД. Нужна сеть только с loopback. Повторные точные тексты в пределах одного задания используют уже вычисленный исход. При потере родителя Linux останавливает дочерний процесс. Пределы — 120 секунд и 2 ГиБ RSS дочернего процесса. Лимиты поставки — 4 МиБ и 10 000 входных позиций. Серверный SQL-запрос worker ограничен 10 секундами. Превышение предела заканчивает попытку.
4. На запись каждой партии проверяются актуальная власть, токен lease, версия и SHA исходника, допустимость позиций и отсутствие повторяющегося version_id. Партии фиксируются в коротких транзакциях. При смене аренды старая генерация удаляется. Повтор начинается с первой версии. До окончательной публикации ни одна строка не видна в выдаче.
5. Финальная транзакция повторно сравнивает полный набор UUID с запечатанным снимком и журналом принятых позиций. Проверяются счётчики, SHA и точное содержимое объекта. Статус succeeded, связанный артефакт и видимый набор появляются вместе. Упавший после записи файла worker может оставить объект без связи. Повтор сверяет содержимое и использует тот же объект. Отмена, потеря допуска и пустой вычисленный числитель — разные состояния.
6. Чтение требует HTTPS, действующих полномочий и удостоверения хранилища. Объект отдаётся по короткоживущему билету с конкретным назначением, run, получателем и SHA. В базе runtime читает через ограниченные функции. Ответ содержит до 25 строк, фильтр и полное число совпадений. Выбор версии отзыва открывает исходный контекст. Параметры адреса содержат идентификаторы, тип исхода и смещение страницы. Обычные ответы и manifest ограничены 64 КиБ.

## Бухгалтерия снимка

`N_input = N_accepted + N_quarantine + N_confirmed_duplicate`. Профиль корпуса использует `N_eligible = N_accepted − N_excluded`. Счётчик `N_evaluated` включает все машинные исходы и воздержания. Полный run требует `N_not_evaluated = 0` и точного равенства множеств версий. Для полной сводки выполняются следующие равенства.

| Величина | Определение |
|---|---|
| N_mentioned | complaint + mixed + denial + positive + neutral + unclear |
| N_evaluated | N_mentioned + not_mentioned + topic_uncertain |
| N_complaints | complaint + mixed |
| N_uncertain | topic_uncertain + unclear |
| Вычислительное покрытие | N_evaluated / N_eligible |
| Покрытие определёнными решениями | (N_evaluated − N_uncertain) / N_eligible |
| Доля машинных жалоб во всём пригодном снимке | N_complaints / N_eligible |
| Доля машинных жалоб среди упоминаний | N_complaints / N_mentioned |

При нулевом знаменателе API возвращает null. Обе доли доступны только у завершённого run. На ручном арифметическом примере из 12 позиций приняты 8, в карантине 3 и подтверждён один повтор. У двух принятых нет текста. Шесть заданных машинных исходов дают 4 упоминания и 2 жалобы, включая mixed. Получаются 2/6 среди пригодных и 2/4 среди упоминаний. Это проверка вычисления по заданным меткам.

## Экспорт, удаление и восстановление

Операторский owner-export содержит разрешённые ссылки и данные в границах источника, проекта или workspace. У завершённого run экспортируются привязка, manifest и строки с SHA. У незавершённого — сведения о привязке, без промежуточных решений. Документ не включает секреты сессии и токен lease. Удаление источника очищает его запуски и результаты, сохраняя независимые определения проекта. Удаление проекта или workspace распространяется и на принадлежащие ему определения. После миграции требуется свежая печать прав. Восстановление выполняется в независимой пустой копии с актуальным внешним ledger. Стирание существующих резервных копий не проверено. [Операторский процесс](retention-operations.md)
