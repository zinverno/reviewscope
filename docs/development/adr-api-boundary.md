# ADR PR-06 · Граница между клиентом, HTTP API и аналитическим ядром

**Решение принято для локального прототипа.** Контракт API ожидает ручного ревью владельцем.

## Контекст и решение

Будущему клиенту на React/TypeScript нужны страницы отзывов и проверяемые основания показателей. Клиент отвечает за навигацию и визуализацию. FastAPI читает выбранный оператором снимок DuckDB и преобразует результаты в HTTP JSON v1. Для расчёта точки он вызывает существующий Python `AnalysisEngine.analyze`. Движок остаётся единственным источником аналитических вычислений, порогов и объяснений. Streamlit сохраняет совместимый локальный путь с прямым вызовом того же ядра.

Выбрали FastAPI и уже используемый Pydantic, чтобы типы ответов, проверка параметров и OpenAPI опирались на одни модели. Вариант с ручной сериализацией и отдельной схемой потребовал бы сверять два описания контракта. Перенос детекторов в JavaScript или новые операции анализа в HTTP-слое создали бы вторую реализацию весов, контраргументов и прямых пар. Клиент получает их из ядра.

DuckDB и движок синхронны. Один процесс владеет одним read-only соединением и одним движком. Синхронные обработчики используют общий `Lock` при обращении к ним. Асинхронная обёртка сама по себе не сделала бы эти объекты безопасными для параллельного использования. Отдельный движок на запрос потребовал бы повторно загружать историю и кэш векторов.

## Следствия и граница следующего этапа

- Тяжёлый анализ занимает lock. Другие запросы к данным ждут его освобождения. Preflight допускает до 5 000 отзывов в снимке, анализ — до 256 на точку. Смена файла требует перезапуска. Проверки на синтетике подтверждают передачу результатов ядра. Качество ML на клиентских данных требует отдельной оценки.
- Путь к единственному доверенному снимку выбирает процесс. В HTTP нет выбора файла или SQL. Сервис слушает только loopback. Авторизация и выдача разрешений CORS отсутствуют. Публичная эксплуатация с реальными отзывами запрещена.
- План PR-07 предусматривает PostgreSQL для операционных идентичностей, истории и прав, а также неизменяемые снимки DuckDB для анализа. PR-07 должен определить связи владельца, источника, снимка и запуска. В PR-06 идентификатор выполнения служит только для диагностики в текущем процессе. Изоляция рабочих пространств относится к PR-08, отдельный worker — к PR-11.
