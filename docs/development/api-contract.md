# PR-06 · Локальный HTTP API v1

**NEEDS_API_CONTRACT_REVIEW.** Клиент читает один выбранный оператором снимок. Четыре GET возвращают JSON. Машиночитаемая схема доступна в `/openapi.json`. Имена полей, типы, единицы, порядок страниц и значения ошибок ниже относятся к `/api/v1`. Несовместимое изменение требует новой версии маршрута.

## Запуск из checkout

Из корня репозитория, Python 3.12 или новее. Extra `api` добавляет FastAPI и Uvicorn. Базовый пакет уже использует Pydantic 2. Синхронные обработчики вызывают Python-ядро напрямую, а FastAPI строит OpenAPI по возвращаемым моделям. Lifespan связывает preflight и закрытие DuckDB с одним запуском сервиса. [Документация FastAPI](https://fastapi.tiangolo.com/advanced/events/)

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e '.[api,dev]'
python scripts/build_public_demo_dataset.py --verify
RS_PUBLIC_DEMO=1 python -B -m reviewscope.api
```

Штатный запуск слушает только `127.0.0.1:8000`, в одном процессе. Разрешённые HTTP Host — `127.0.0.1` и `localhost`. Доступа для других origins нет, access log выключен. Для остановки нажмите Ctrl+C. Авторизация отсутствует. Публичное размещение с реальными отзывами запрещено, включая проксирование и туннели.

В соседнем терминале:

```bash
api=http://127.0.0.1:8000/api/v1
curl -fsS "$api/health"
curl -fsS "$api/places"
curl -fsS "$api/places/p1/reviews?limit=1&offset=0"
curl -fsS "$api/places/p1/analysis"
curl -si "$api/places/p1/reviews?limit=101"
```

## Источник и ресурсы

- По умолчанию процесс открывает `demo/reviewscope_demo.duckdb` из checkout и сверяет SHA-256 с соседним `manifest.json`. Явное `RS_PUBLIC_DEMO=1` закрепляет этот выбор даже при заданном локальном пути. Секреты и настройки выбора файла из Streamlit в HTTP-конфигурацию не входят.
- Для **доверенного локального снимка** администратор может запустить `RS_PUBLIC_DEMO=0 RS_API_DB_PATH=/absolute/path/to/snapshot.duckdb python -B -m reviewscope.api`. Нужны обычный файл, схема ReviewScope и уже рассчитанные совместимые векторы для всех отзывов, включая нулевой вектор для пустого текста. Фабрика `reviewscope.api.create_app(db_path=Path(...))` даёт ту же возможность Python-хосту. Эти параметры существуют только внутри процесса.
- При старте открывается один `DuckDBStore(read_only=True)`. Внешний доступ DuckDB отключается. API проверяет таблицы и вызывает `EmbeddingCache.missing_keys` по всему снимку. Этим учтены точный текст, идентичность кодирования, размерность и допустимость вектора. Упакованное демо использует замороженный контракт PR-04. Режим `precomputed_only` запрещает вызов encoder даже при последующем промахе. [Контракт векторов](embedding-contract.md)
- Один lock сериализует обращения к connection и `AnalysisEngine`, включая анализ. Health читает готовность уже открытого снимка. При неудачном preflight соединение закрывается сразу. При штатной остановке оно закрывается после последних запросов. После ремонта или замены файла перезапустите процесс. GET не меняет снимок, не создаёт кэш или базу.
- Предел снимка — 5 000 отзывов. Это ограничивает стартовую проверку и историю авторов, которую читает движок. Для анализа предел одной точки — 256 отзывов (до 32 640 возможных пар). Список и страницы доступны и для более крупной точки внутри допустимого снимка. В пределах лимита выдаются все события, участники и прямые пары выбранного анализа. Усечения графа и скрытого пересчёта по выборке нет.
- Streamlit продолжает пользоваться Python-ядром. Прототип React работает со своими фикстурами. Будущий клиент может опираться на v1 без доступа к DuckDB, приватным атрибутам движка или сериализации DataFrame.

## Ресурсы

### GET /api/v1/health

HTTP 200 означает, что HTTP-сервис отвечает. При готовом снимке:

```json
{"status":"ok","api_version":"v1","dataset_available":true}
```

Если файл отсутствует, повреждён, превышает лимит, имеет несовместимую схему или неполный кэш, HTTP 200 возвращает `{"status":"degraded","api_version":"v1","dataset_available":false}`. Три маршрута данных тогда возвращают 503.

### GET /api/v1/places

Массив, одна запись на `place_id`, сортировка по этому ID по возрастанию. Пустой снимок с корректной схемой даёт `[]`. Для имени и категории берётся лексикографически первое известное значение данного поля. Пара координат берётся из одной записи с наименьшим `review_id` среди записей с обеими координатами в допустимых диапазонах. Порядок — [широта, долгота]. Каждое из трёх необязательных значений может быть `null`. Первая запись из упакованного демо:

```json
{"place_id":"p1","name":"Кофейня «Зерно»","category":"coffee","review_count":204,"coordinates":[55.7558,37.6173]}
```

### GET /api/v1/places/{place_id}/reviews

`limit` от 1 до 100, по умолчанию 25. `offset` от 0 до 2 147 483 647, по умолчанию 0. Порядок по времени публикации от новых к старым, затем по `review_id` по возрастанию. Отсутствующая или нечитаемая дата идёт последней. Время приводится к UTC, строка в JSON содержит `Z`. Дату без смещения хранилище трактует как UTC. SQL считает total отдельно и выбирает только нужную страницу через параметры LIMIT/OFFSET. Страница за концом даёт HTTP 200, исходный total и пустой массив. Точки определяются по хранимым отзывам, поэтому неизвестный ID даёт 404.

Пример полного ответа демо для `p1?limit=1&offset=0` на маршруте отзывов:

```json
{
  "place_id": "p1", "total": 204, "limit": 1, "offset": 0,
  "reviews": [{
    "review_id": "r00972", "rating": 5, "published_at": "2026-09-21T16:33:00Z",
    "text": "В следующий раз попробую что-то новое Взял напрокат другое, остался доволен По рекомендации стоматолога попробовал новое. Зерно недавней обжарки, кислинка приятная. Заказал капучино, приготовили без задержки. Капучино получился ароматным. Атмосфера расслабляющая.. Павел похвалил флэт уайт. Спросил про ингредиенты, ответили уверенно."
  }]
}
```

В каждой записи `text`, `rating` (1–5), `published_at` допускают JSON null. Идентификаторы сохраняются из снимка.

### GET /api/v1/places/{place_id}/analysis

Ответ — проекция одного вызова `AnalysisEngine.analyze(place_id)`. Числа ниже получены на упакованном демо 23 ноября 2026 года. Вес отзыва в ядре может зависеть от давности.

| Поле | Значение |
| --- | --- |
| `place_id`, `review_count`, `rated_review_count` | ID, число отзывов, число с указанными звёздами. Для p1 — 204 и 204. |
| `raw_rating` | Среднее ядра по имеющимся оценкам, для p1 — 4.19 звезды. При отсутствии оценок — null. |
| `calculated_weighted_rating`, `rating_notice` | Объяснение взвешенного рейтинга и обязательное предупреждение об отличии модели ReviewScope от официального рейтинга площадки. У p1 — 4.12 звезды. При отсутствии оценок значение внутри объяснения равно null, свидетельство ядра сохраняется. |
| `coordinated_activity` | Score ядра, у p1 — 58.7/100, MEDIUM. Сигналы описывают наблюдаемые свойства выборки. |
| `burst_events` | Все события объёма. ISO-дата, ожидаемое и наблюдаемое число (`expected`, `observed`), `severity` и оба списка свидетельств. В v1 множитель не выдаётся. Для 2026-09-02 у p1 эти числа равны 0 и 30. |
| `rating_anomalies` | ISO-дата, `baseline_dist`, `event_dist` (ключ — число звёзд строкой, значение — доля), `jsd`, `severity`, оба списка свидетельств. |
| `duplicate_groups` | `group_id`, `review_ids`, оба списка свидетельств и `edges`. Элемент edges — [review_id_a, review_id_b, kind, similarity]. Только сохранённые прямые неориентированные пары. Для A–B–C рисуют A–C только при наличии этой пары. `kind` принимает exact, fuzzy, near, semantic. Число отзывов — длина review_ids, число прямых пар — длина edges. |
| `topics` | `cluster_id` (число либо специальное значение ядра "all"), `review_ids`, `representative_phrases`, `representative_reviews` ([review_id, similarity]), оба списка свидетельств. Идентификаторы кластеров и групп действуют только внутри расчёта. Для межпериодного issue ID нужен отдельный контракт. |

Оба типа score сохраняют `name`, `value`, `unit`, `confidence` (LOW/MEDIUM/HIGH), `signals`, `counter_signals` и полный числовой `details`. API указывает единицу рейтинга `stars`, поскольку модель ScoreResult по умолчанию подставляет `/100` и для этого результата. Отсутствующий объект score передаётся как null. Пустой массив событий или тем означает, что ядро ничего не вернуло в этой категории на доступных данных. Текстовые свидетельства передаются на языке ядра. Клиент отображает их как текст.

Полный вложенный score p1:

```json
{"name":"Weighted Rating","value":4.12,"unit":"stars","confidence":"HIGH","signals":["weighted rating is lower than raw average"],"counter_signals":[],"details":{"raw":4.19,"delta":0.066}}
```

У p1 получены 2 всплеска, 2 изменения распределения оценок, 9 семей повторов и 4 темы. Пример реально возвращённой прямой пары — `["rbp000","rbp001","semantic",0.9315310716629028]`. Для coordinated activity ядро также вернуло контраргумент `reviews spread across many distinct reviewers`. Эти результаты служат проверкой передачи данных.

## Ошибки

Тело ошибки содержит единственное поле, например `{"error":"invalid_request"}`. Пользовательский ввод, путь, текст исключения и traceback в ответ не попадают.

| HTTP | error | Условие |
| --- | --- | --- |
| 400 | invalid_host | Чужой Host. |
| 404 | not_found | Неизвестный маршрут или точка в доступной базе. |
| 405 | method_not_allowed | Метод, отличный от GET, на маршруте v1. |
| 413 | analysis_limit | Запрошен анализ точки более чем с 256 отзывами. |
| 422 | invalid_request | Значение пагинации вне контракта, повторный или неизвестный query-параметр, непустое тело GET. |
| 500 | internal_error | Неожиданная ошибка чтения, анализа или подготовки JSON. |
| 503 | dataset_unavailable | Preflight не открыл допустимый снимок. |
