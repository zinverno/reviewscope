# PR-12. Жизненный цикл данных локального workspace

**NEEDS_RETENTION_CONTRACT_REVIEW** · контракт `retention-1`. Зависимости дорожной карты — 08, 10 и 11. Рабочая модель допускает несколько проектов в одном workspace и несколько поставок на источник. Идентичность поставки задаёт её UUID в области источника. Ключ повтора заявки уникален в workspace. Внешние ID отзыва и SHA файла служат другим целям.

## Граница выполнения

Вход по сессии, членству, RBAC и RLS на loopback 8001. На 8000 и в Streamlit остаётся отдельный публичный DuckDB. PR-11 читает `canonical-json-v1` из исторической колонки `snapshot.duckdb_sha256` и выпускает `snapshot_integrity_and_summary_v1`. Облачный импорт данных клиента, анализ ML и самостоятельный frontend остаются закрытыми.

Владелец видит preview исходных ссылок и количества строк по таблицам, заказывает экспорт и задаёт правила своего источника. Analyst и viewer читают сроки, их доступ к приватным строкам закрыт. Выдача фактического ZIP и подтверждение удаления требуют локального оператора с проверкой получателя и области. **OWNER_EXPORT_REQUIRES_OPERATOR**. HTTP GET читает metadata. SHA и UUID не дают разрешения на скачивание.

## Решение о сроках

Политика принадлежит конкретному source в проекте и workspace. Для каждого класса владелец указывает основание вне системы (UUID подтверждения), период хранения, начало отсчёта и период пересмотра. Удержание требует отдельного UUID. Отсутствующая запись даёт `unset`, отсутствующая дата даёт `null`. Оператор проверяет актуальность права для данного места обработки, операторов, получателей и резервирования. Договор, юрисдикция и реальные сроки для пилота не утверждены.

GET источника с суффиксом `/retention` отдаёт страницы по 50 записей, следующие страницы выбираются `offset`. У классов без привязанного объекта срок имеет неизвестное окончание. Ручной POST `/retention/sweep` сопоставляет часы каждой связанной записи с утверждённым правилом. Полностью просроченный источник с подтверждённым покрытием получает обычную заявку с preview. Неизвестное покрытие, неутверждённое правило, неизвестный якорь, удержание, действующий срок и просроченный пересмотр блокируют автоматический выбор. Частичное покрытие описывает только доставленный набор. Неодновременное истечение классов требует решения владельца о связанном наборе. Локальная схема PR-10 связывает исходник, каноническую проекцию и журнал неразрывным manifest. Для договора с раздельными жёсткими дедлайнами классов этот профиль имеет статус **BLOCKED_RETENTION_POLICY**.

## Порядок удаления

1. Owner отправляет `POST /api/v1/workspaces/{w}/retention`. В preview есть области, количества строк, ссылки (source, parent, класс, SHA), SHA с живой ссылкой за выбранной областью и внешние исключения. Повтор ключа возвращает ту же заявку. Смена действия или scope с тем же ключом даёт 409.
2. Оператор проверяет владельца и digest preview. Повторная проверка под общей блокировкой учитывает актуальные права, удержание и граф. До commit удаления атомарно записывается независимое запрещение. Между публикацией запрета и отражением в PostgreSQL чтение и публикация закрываются при несовпадении свидетельств. При обрыве оператор повторяет подтверждение той же заявки.
3. В одной транзакции `revoking` ограниченная функция удаляет операционные строки выбранной области в порядке FK, включая активные и завершённые задания и выдававшиеся их metadata. Старый lease теряет запись и получает `stale`. Временная отсрочка проверки циклического FK run/artifact действует до проверки ограничений в той же транзакции. Триггеры неизменяемой истории активны. В БД фиксируются кандидаты на unlink и состояние `purging`. Повторное создание отозванного идентификатора закрыто.
4. В отдельной транзакции оператор проверяет SHA и тип файлов и фиксирует разрешение на повторяемый unlink. Перед unlink ещё раз проверяются все ссылки workspace. Роль не имеет DELETE над частными таблицами. Все штатные файловые писатели и очистка используют общий порядок блокировок. На чистом завершении отражаются `verifying` и `completed`. Ошибка ФС оставляет `failed` для повторного выполнения. Неожиданная запись, повреждение или отсутствующий до проверки файл требуют сверки с проверенной копией. Молодой сиротский файл остаётся в `purging` минимум до истечения 60 секунд с mtime. Это окно безопасности для файлов в приватном пространстве SHA, срок хранения данных источника задаётся отдельно.
5. Реестр хранит минимальный запрет независимо от базы. Удаление workspace оставляет его UUID для запрета восстановления. Пользовательские выгрузки после передачи владельцу находятся вне контроля сервиса.

## Матрица мест хранения

| Место / класс | Проверяемый результат для выбранной области | Исключение или граница |
| --- | --- | --- |
| PostgreSQL source, привязки, позиции accepted/duplicate/quarantined, identity/version, автор, текст, URL, metadata | erased при логическом удалении строк, проверка графа и FK | Физическое затирание страниц MVCC, WAL и носителя не аттестовано |
| Project, location, workspace, membership, membership_event | при полном scope удаляются соответствующие строки; у source удаляются только связанные с ним бесхозные location | retained_with_reason для живой общей точки и родительских объектов |
| Raw, mapping, паспорт формата, паспорт покрытия | сверка ссылок и SHA, затем erased или retained_with_reason | Одинаковый SHA в другом workspace имеет собственный ключ |
| Snapshot, members, manifest, canonical JSON Lines; исторический синтетический DuckDB | снятие связей, проверка файлов и удаления | Оригинал публичного демо вне операционного workspace; его SHA проверяется отдельно |
| Очередь, lease, analysis_run, artifact и сводка PR-11 | строки и доступ к результату отозваны; байты учитываются по SHA | Повтор публикации старым lease закрыт |
| Экспорты | отозваны заявки на пересекающийся набор; ZIP публикуется сразу в проверенную владельческую зону | external_uncontrolled после передачи; незавершённый ZIP использует безымянный файл |
| Временные и осиротевшие объекты | только в проверенном workspace/sha256, после паузы и повторной проверки ссылок | неизвестное имя/тип блокирует завершение, исходные файлы оператора вне root — external_uncontrolled |
| Эмбеддинги, поисковый индекс и кэш управляемого workspace | not_applicable | PR-11 создаёт только сводку; демо и кэши чужих приложений отдельно |
| Служебная диагностика и доступ | retained_with_reason для технического статуса, UUID, дат, размера и аудита переходов | общие account, credential и session принадлежат логину; членство и доступ к удалённой области прекращаются |
| PostgreSQL dump, архив объектов, WAL, журналы хоста и иные копии | BACKUP_ERASURE_NOT_VERIFIED до проверки инвентаря, срока и ротации оператором | Внешние скачивания external_uncontrolled. Восстановление обслуживает только актуальную разрешённую область |

`completed` относится к проверенным живым путям локального сервиса. Журнал запрещений должен жить дольше самой старой допустимой точки восстановления. Проверки конкретной установки и процедура ротации приведены в [операторском руководстве](retention-operations.md).
