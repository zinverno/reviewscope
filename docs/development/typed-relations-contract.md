# Прямые отношения в загруженном снимке

**NEEDS_TYPED_RELATION_CONTRACT_REVIEW · SYNTHETIC_EVIDENCE_ONLY**

В кабинете откройте загруженный синтетический снимок, «Повторы выбранного снимка» → «Отношения между отзывами». Это текстовый режим. Для сопоставления позиций откройте сохранённую редакцию ручной проверки и выберите «Отношения по этой редакции». В списке и на схеме одна строка соответствует одной сохранённой неупорядоченной паре разных версий. Ссылка открывает обе исходные записи. Отдельные UUID сохраняются даже при равном тексте.

### Что означает ребро

| Ось или основание | Условие и смысл |
|---|---|
| Канал exact | Равенство UTF-8 либо равенство после ICU lower и свёртки пробелов. Сохраняются режим и SHA оригинала и нормализованной строки. Пустые версии исключены. |
| Канал shared_words | Число разных общих токенов длиной от четырёх символов. Разделитель — пробел в нормализованной строке. Хранится счётчик и, когда общий токен буквально присутствует с обеих сторон, два точных интервала. Пунктуация и перефразирование могут привести к пропуску. |
| Текстовая ось | `exact_text / deterministic_text` либо `text_similarity_candidate / machine_experimental`. Для пары, отобранной только по решениям, текстовая гипотеза имеет статус `not_evaluated`. Экспериментальная метка близкой копии вынесена в исследование качества. |
| Канал frozen_endpoints | Оба события входят в выбранный опубликованный результат PR-23. События disputed тоже могут объяснить попадание в очередь пар. |
| Аспектная ось | Два однозначных complaint с пригодными цитатами дают `same_specific_complaint`. Complaint и denial с цитатами дают `opposite_stance`. Обе позиции относятся к одному конкретному определению. |
| Происхождение | `derived_from_human_outcomes` означает вывод из двух ручных решений по отзывам. Независимая ручная оценка пары отсутствует. Рейтинг и предполагаемая личность автора в расчёт не входят. |
| Остальные исходы | Dispute, mixed, unclear, topic_uncertain, отсутствие одного события или обязательной цитаты дают `uncertain`. Остальные разрешённые сочетания дают `no_relation`. Без редакции аспект получает `not_evaluated`. |

Поддержаны две точные редакции payload PR-20/22. A описывает очередь **до оформления**, B — задержку **передачи уже готового заказа**. Для обеих приготовление и неопределённый этап исключены. Привязка включает workspace, project, source, snapshot, run решения, aspect ID, version ID, digest определения, UUID и digest human result. SQL сверяет digest поддержанного определения в сериализации PostgreSQL JSONB. Для A он равен `d4614d09b445e4a27bb2fd7690646ec6cfbe3aceddd3968e9c2d406710ad6848`, для B — `7f3c7010e46abc7e3e309feb0618f71c954e6eaab6b8904e5f299bc66e04ea48`. В offline-корпусе SHA того же payload вычислен из компактного упорядоченного JSON для переносимого воспроизведения. Остальные определения доступны в прежних инструментах. Например, два отзыва с жалобами на разные свойства еды не становятся одной конкретной проблемой.

Ключ пары — упорядоченные version UUID внутри immutable result. Роли, event UUID, интервалы Unicode `[start,end)`, content SHA и text SHA остаются при своих версиях. Новое событие PR-23 влияет только на граф, построенный по новой опубликованной редакции. A–B и B–C сами по себе не создают A–C. Пропущенная пара не имеет классификации.

### Границы и хранение

`direct-pairs-small-v1` — синхронная SQL-проекция максимум 32 принятых версий, 4 КиБ UTF-8 на текст, 496 сравнений, 24 новых результата за час на workspace. Брокер читает до 4 МиБ канонического объекта. Профиль без векторов. Для большого снимка доступна явная причина `VERSION_LIMIT`, для длинного текста — `TEXT_BYTE_LIMIT`; POST получает 413. SQL ограничен 10 секундами. Внешнего inference нет. Текстовое равенство проверяется на всех пригодных парах этого малого снимка. Полнота аспекта ограничена отбором и ручной проверкой концов.

Миграция `0018_typed_relations` добавляет `browser_admission.relation_allowed DEFAULT false`, `relation_result` и `relation_pair`. В одной транзакции до записи вычисляются число и упорядоченный SHA предложенных рёбер. При расхождении с независимо вычисленными числом и SHA записанных строк публикация отменяется. Ключи строк дополнительно сверяются с обоими version UUID в свидетельстве. Временных файлов и промежуточных видимых состояний нет. Потеря соединения до commit отменяет обе записи. Публикация сериализуется в workspace. Повтор с теми же ключом, актором и привязками возвращает прежний UUID, конфликт даёт 409. Очередь, lease и отдельная кнопка отмены к этой синхронной операции не применяются.

Составные FK связывают result с источником, snapshot, запуском решения и human revision, а оба конца пары — с membership того же snapshot. Триггеры защищают изменения и truncate. Manifest включает бюджеты, числители по осям, хеш упорядоченных строк, их индивидуальные контрольные суммы, SHA текста определения функций профиля и версии исходных свидетельств. UUID новой попытки и время не входят в смысловой digest. Выдача страницы использует индексы и проверяет контрольные суммы её строк; восстановление и owner export дополнительно сверяют полный набор с независимой проекцией immutable родителей.

### Доступ и API

Префикс `/api/v1/workspaces/{w}/snapshots/{s}/relations`. Все методы требуют локальный TLS, действующую сессию owner/analyst, живой retention witness и допуски evidence, candidate, relation для SHA именно принятого синтетического файла. Режим с редакцией дополнительно требует decision и human grant, завершённый run и его проверенный объект. Брокер получает ограниченный по времени билет, проверяет область, актуальный root и байты snapshot. Отзыв допуска закрывает ранее опубликованный результат. Права runtime, upload и worker на произвольное чтение или запись новых таблиц отсутствуют.

| Запрос | Параметры | Ответ |
|---|---|---|
| GET базового пути | source_id, опциональная пара decision_run и human_revision | Пределы, число версий, причина ограничения |
| POST базового пути | Те же поля в JSON и idempotency_key, Origin, X-RS-CSRF | 201/200, UUID сохранённого результата |
| GET /{result} | source_id, offset, optional exact_only и digest | Общий manifest и до 10 прямых пар. Фильтр меняет только filtered и список |
| GET /{result} | source_id, left, right, digest | Два точных оригинала, SHA, собственные интервалы и происхождение |

Предельный обычный ответ и manifest — 64 КиБ. Схема отображает до 10 прямых рёбер / 20 узлов. При выборе детали проверяются оба UUID, SHA и границы. Переходы страницы, Back/Forward, focus, pagehide, смена видимости и периодическая проверка закрывают устаревшее содержимое. Формы не записывают тексты в localStorage.

### Экспорт, очистка и восстановление

План retention включает численность обеих таблиц и байты сериализованных manifest/evidence. Owner export выбирает строки через RLS по источнику, проекту или workspace. Ключи идемпотентности и учётные данные исключены. Удаление проходит по составным FK и прежнему внешнему deletion ledger. При восстановлении старой копии оператор проверяет текущий ledger, новую печать схемы/прав и содержимое независимого объектного root. По умолчанию прежний business seal не меняется. Каталожная печать меняется. Для штатного порядка обновления и допуска отдельной копии см. [операции retention](retention-operations.md). Downgrade работающей БД запрещён.

### Воспроизведение

Из независимой рабочей копии с установленными штатными зависимостями и собранным кабинетом:

```sh
python -m pytest tests/test_typed_relations.py tests/test_cabinet_graph.py
RS_MEASURE_RELATIONS=1 bash operational/test-isolated.sh -s -k 'typed_relations or relation_snapshot_profile'
bash operational/test-isolated.sh -s -k 'decision_retention or decision_upgrade or cabinet_native'
```

Каноническая выдача на снимках сверх лимита остаётся `CANONICAL_GRAPH_NOT_AVAILABLE`. Исследовательский producer на 10k, замороженные qrels и компактные показатели описаны отдельно. [Оценка и измерения](typed-relations-results.md) · [Протокол до holdout](../../tests/data/relations/protocol.md)
