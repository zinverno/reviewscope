# PR-18 · Контекст автора в предоставленных отзывах

В кабинете откройте исходный отзыв и выберите «Контекст автора». В публичном обзоре точки также доступен список авторов. Каждая строка истории ведёт к первичной версии с её исходной оценкой и текстом. Даты ограничивают период наблюдений в наборе. Физическое посещение, место жительства, работа, маршрут и полнота активности автора неизвестны.

## ADR · идентичность и происхождение

| Вопрос | Упакованная синтетика | Операторский синтетический снимок |
|---|---|---|
| Кто входит в историю | SHA DuckDB, точное значение source, точный непустой reviewer_id. Имя используется только для описания исходной записи | Workspace и source из зарегистрированной поставки, её точный source_reviewer_id, только принятые version_id выбранного snapshot |
| Нет авторского ID | Запись остаётся в исходной выборке, в списке авторов учитывается как пропуск, переход даёт NO_REVIEWER_ID | Разрешённый отзыв остаётся доступен. NO_REVIEWER_ID для привязанной версии, история отсутствует. Quarantine и confirmed_duplicate в состав не входят |
| Место и категория | place_id, place_name, place_category, city и region из соответствующей строки DuckDB | source_location связывает ключ источника с location в проекте. Доступны идентификатор и имя точки. CATEGORY_METADATA_UNAVAILABLE |

| Даты и оценки | Календарная часть исходного published_at и целая оценка 1–5. Пропуски видны в знаменателях | Для периода учитываются published/submitted с однозначной датой или instant в UTC. Диапазон, распределение и среднее относятся к сохранённым допустимым значениям. При пустой выборке среднее равно null |

Область публичного результата зависит от точки. Для p1 берутся авторы, у которых есть хотя бы один отзыв о p1. Детекторы повторов и шаблонности работают на всех отзывах этих авторов в их источнике. Личные доли считаются внутри этой выборки. Параллельно сохранены значения для всего корпуса источника. На frozen demo обе доли совпали во всех 501 сравнениях. При изменении соседних текстов результат текстовых детекторов может измениться.

### Публичные формулы и единицы

- Для автора сохраняются число записей, различные категории и города, первая/последняя известная дата, средняя длина текста в символах и конкретика по шкале 0–100. Legacy-агрегация включает пустой текст как строку длины 0. Active period использует минимум один день при наличии известной даты. В интерфейсе отдельно видны календарные границы.
- Для известных оценок используются среднее, стандартное отклонение генеральной совокупности и энтропия частот пяти звёзд в битах, делённая на log₂(5). Поле review_diversity равно единице минус эта энтропия. Consistency зависит от разброса оценок. При отсутствии основания технический sentinel сохранён для сверки. Для пользователя показатель Н/Д.
- Category experience применяет log-сатурацию `min(1, log10(n+1)/3)` к числу отзывов в категории и глубине истории. Веса объёма, доли с поправкой на глубину, периода и различных мест составляют 0,35/0,40/0,15/0,10. Доля записей по категории доступна из счётчика категории и общего N.
- Local familiarity использует количество отзывов, число различных мест и календарный размах в городе или регионе. В региональную группу входят другие города того же региона. При наличии обеих групп прежнее правило смешивает их компоненты 0,75/0,25. Техническое поле duration содержит нормированный составной индекс и не измеряет длительность.
- Для reviewer relevance вычислитель использует category experience, среднюю конкретику, концентрацию оценок, local familiarity и log-глубину истории. Компоненты считаются до округления деталей. Итоговые три индекса имеют шкалу 0–100 и категориальный evidence band. Полная конфигурация и отдельные знаменатели сохраняются вместе с результатом. Исходы PR-17 и его веса рассчитываются прежним путём на 2026-11-24.

## Закрытый снимок

`GET /api/v1/workspaces/{w}/snapshots/{s}/reviews/{version}/reviewer-context?source_id={source}&offset=0&limit=25` выполняет ограниченное чтение. Входом служит version UUID. Ответ содержит привязку к workspace, source, snapshot, anchor, manifest SHA и версии метода. Собственные строки истории имеют version UUID, дату, точку и исходную позицию. Значение метода `snapshot-reviewer-context-v1`. Параметр limit допускает 1–50, кабинет показывает по 25. Counts и распределение относятся ко всем допущенным версиям автора в этом снимке. При пустом допуске истории для известного ID возвращается AUTHOR_CONTEXT_NOT_ADMITTED. Для неизвестного или чужого anchor действует 404, для viewer действует ограничение роли, отсутствие сессии или доступного witness закрывает выдачу.

Раздел availability содержит computed, insufficient_data или not_available, числитель eligible, знаменатель total и причину для мест, дат, оценок, конкретики, категории, географии и релевантности. При отсутствии допуска оба счётчика неизвестны. При наличии истории с отсутствующими оценками количество известных оценок равно нулю, среднее остаётся null.

| Проверенная каноническая поставка | Принятые версии с ID / без ID | Остальные позиции | Доступный результат |
|---|---:|---|---|
| A | 0 / 3 | 0 из 3 | Исходные версии, оценки, конкретика при наличии текста |
| B | 0 / 6 | 0 из 6 | Те же операции, включая исправленную версию |
| Проблемный JSON | 0 / 6 | 5 в карантине, 1 подтверждённый повтор из 12 | Все 6 принятых версий открываются по своему UUID |
| Операторский пример | 3 / 2 | 2 в карантине, 1 подтверждённый повтор из 8 | У первого автора 2 записи о разных местах и средняя 3 из 2 оценок, в исправленном снимке 4,5. Второй точный ключ даёт отдельную историю из 1 записи |

Оператор проверяет синтетические байты и область поставки до включения отдельного `browser_admission.author_context_allowed` для точной тройки workspace_id/source_id/checksum. Default false действует также для существующих строк при миграции. У браузерной загрузки запрет на передачу авторского ID сохраняется. Вычисление использует одну SQL-проекцию по version ID и актуальной записи допуска. Исторический снимок воспроизводит собственную редакцию. API не создаёт новый run, не требует моделей или векторного backend и не выдаёт исходный reviewer_id. При несовместимости ревизии, потере членства или допуска защищённые данные закрываются. В канонической области category experience, local familiarity и полный reviewer relevance недоступны.

### Хранение, откат и восстановление

| Объект | Жизненный цикл |
|---|---|
| Право чтения истории | Новая колонка существующего browser_admission. Отзывается оператором на конкретном SHA. Access seal учитывает всю строку и функцию с её ACL. При erase/purge действует существующий жизненный цикл допуска источника |
| SQL-функция | Forward-only миграция после 0010_signals. Вызывать проекцию может runtime при наличии доказательства сессии и членства. Процессам upload и worker для неё не нужны новые права |
| Производные канонические данные | Отдельных таблиц историй, артефактов, файлов и кешей нет. При каждом запросе история формируется из разрешённых строк. Экспорт исходных версий выполняет оператор |
| Offline-части демо | Только замороженная публичная синтетика в Git. Для пересборки сверяются хэши источника и исходных версий |

Чтобы немедленно закрыть функцию для поставки, оператор отзывает отдельное право истории. Откат приложения с физическим восстановлением выполняется только по согласованной процедуре резервной копии с независимо зафиксированными access seal и deletion ledger. Применять downgrade к живой БД не предусмотрено. Статусы **OWNER_EXPORT_REQUIRES_OPERATOR** и **BACKUP_ERASURE_NOT_VERIFIED** сохраняются. ### Контроль паритета и границы нагрузки

Из принятого дерева PR-17 воспроизведены все 143 профиля полного корпуса, 501 состав истории в привязке к точке и 1 503 значения трёх индексов. На каждой привязке сверены все числа ReviewerMetrics и членство по version. Например, у вымышленного u0000 в p1 и p3 индекс локального контекста равен 41,3 и 17,5 соответственно. В отдельной синтетической проверке доля сигнала повторов меняется с 0 до 0,5 при включении соседних текстов в другую когорту.

- Публичный manifest занимает 4 693 байта, его SHA-256 `dad4dfcf7ee1b08cea9e16b54b5a69222078d5226616460ad23a990bf153436c`. В 226 частях 1 361 110 байт, размер одной 608–31 572 байта. Две генерации 227 файлов дали одинаковые байты. На локальном CPU повторный запуск занял 32,18 с с максимальным RSS 309 992 КиБ.
- Offline-путь детекторов ограничен подтверждённым корпусом из 1 058 записей. Отдельная попытка передать 10 000 строк одного автора остановлена до вычисления детекторов, обработано 0 из 10 000. Положительная проверка 10 000 относится к каноническому SQL-пути.
- В disposable PostgreSQL 18.6 проверена поставка ровно 4 194 304 байта, 10 000 принятых позиций, один автор, исключено 0. Полные counts читаются при запросе каждой страницы, конкретика рассчитывается для её 50 строк. Worker этот запрос не запускает. В тесте отдельно измеряются wall time первой страницы, её повтора и последней страницы, размер HTTP-ответа, пиковая память отдельного процесса ASGI/TestClient и обслуживающего PG backend. Фактические измерения для опубликованного HEAD приведены в PR.

Первые два прогона до исправления заняли 39,01 и 40,21 с при таймауте кабинета 12 с. На свежей поставке планировщик без статистики повторно просматривал версии для каждого члена снимка. При 10 000 строк проверка совместимости сделала около 101 млн обращений к буферам. В запросе истории первый вложенный цикл отбросил около 100 млн пар строк. Теперь SQL сверяет упорядоченные версии снимка и принятых позиций с манифестом поставки и использует полный ключ версии, включая identity_id. На тех же 10 000 строк без статистики исправленная проверка совместимости заняла 30 мс, расчёт истории — 36 мс. Названия точек и тексты SQL читает для возвращаемой страницы. Регрессионный тест проверяет таймаут для первой страницы, её повтора и последней страницы до автоматического обновления статистики.

## Закрытие регрессии PR-18

В принятой миграции `0011` проверка состава и построение истории по отдельности читали версию для каждой позиции. На 1 000 принятых строках PostgreSQL 18.6 дважды выбрал `review_version_batch_idx` с Index Cond только по workspace и source. Каждый из 1 000 проходов в обоих узлах отбрасывал в среднем 1 099 строк. На одном наборе из 100 позиций потребовалось 20 804 обращения к shared buffers, на 1 000 — 166 676. В обоих случаях источник содержал 1 100 исторических версий. Счётчик учитывает hits и reads во внутренних операторах, читающих версии.

На чистом merge #22 `91011fb` исходный тест в этом повторе уложился в лимит за 0,1351 / 0,1028 / 0,1284 с. На другой свежей фикстуре с той же принятой функцией диагностические запросы с вложенным EXPLAIN превысили 12 с и в custom, и в generic plan. Для прерванных запросов длительность полного плана неизвестна. Ранее были записаны тайм-аут процесса 120 с на чистом PostgreSQL 18.6 и первая страница 21,6536 с на PostgreSQL 16.16.

Миграция `0013_reviewer_context_plan` заменяет только `reviewer_context_page`. После проверки сеанса, блокировки допуска и сверки snapshot_member с манифестом она соединяет accepted positions с версиями своего workspace/source по UUID. FULL JOIN допускает hash или merge и сохраняет строку поставки при отсутствии версии. Границы отсортированного манифеста ограничивают диапазон UUID. Старые версии внутри диапазона могут быть прочитаны один раз. Барьер после соединения сохраняет его форму при отбрасывании этих версий. Материализуются только позиции поставки. Несовместимая identity, нормализация, лишняя или пропущенная позиция закрывают весь ответ. История и агрегаты используют тот же набор. Тело отзыва разрешается только по ID страницы, до 50. Используются существующие индексы и штатные настройки планировщика.

На том же локальном наборе при generic plan новая функция использовала 387 и 459 обращений к буферам для 100 и 1 000 позиций. Оба обращения к таблице версий имели loops=1. На отдельной фикстуре 10 000 получены Hash Full Join и 12 253 обращения к буферам. Отбор версий использовал полный префикс PK с диапазоном UUID. Чтение страницы один раз прошло индекс workspace/source, отфильтровало 9 950 и вернуло 50 строк. На других планах после ANALYZE встречался один последовательный проход. Тест дополнительно проверяет generic/custom и `random_page_cost=100` внутри отдельной читающей транзакции. Счётчики вложенных планов собираются в реальном вызове runtime/SECURITY DEFINER с ANALYZE, BUFFERS и SETTINGS, формат JSON. Публикуются числовые сводки и имена индексов.
