# Отзывы и панель доказательств

**NEEDS_EVIDENCE_UX_REVIEW.** Оператор локальной синтетической установки разрешает показ канонического текста отдельно от приёма файла. Для существующей и новой записи `browser_admission` значение `evidence_allowed` по умолчанию false. Оператор может изменить его для точной тройки workspace, source и SHA проверенного синтетического файла. Изменение входит в независимый access-seal. Старый dump с прежним допуском требует сверки до открытия API. Решение о раскрытии реальных источников остаётся за владельцем.

На HTTPS 8001 список `/api/v1/workspaces/{w}/snapshots/{k}/reviews` и деталь `/reviews/{version}` доступны действующим owner и analyst в своей области. Viewer сохраняет чтение метаданных и сводки. Порт 8000 обслуживает упакованную демонстрацию. PostgreSQL повторяет проверку текущей сессии, членства, источника и отдельного допуска в узкой функции с фиксированным search_path. Web-роль сохраняет прежние ограничения на чтение приватных таблиц и файлов.

Список строится из принятых позиций конкретной поставки в запечатанном `snapshot_member`. После фильтрации по источнику, точке, звёздам, датам, наличию текста/сопоставимой даты и номеру позиции записи сортируются по позиции и UUID версии. Ответ содержит total и до 50 строк. Деталь проверяет ту же выборку. Дни для моментов времени определяются по UTC, календарные даты сохраняются. Доступны исходное смещение и точность из канонической версии. У позиции без внешнего ID есть собственная внутренняя идентичность. Отдельно представлены поставка выбранного снимка и поставка создания версии. Карантин остаётся в позиционном журнале.

В кабинете ссылка «Отзывы выбранного снимка» открывает список. Ссылка сводки на записи с пригодным текстом задаёт фильтр. Выбор версии, фильтр и страница сохраняются в адресе. Ранее подтверждённый снимок получает пометку истории при наличии более нового разрешённого снимка. После удаления, отзыва разрешения или при чужом UUID API отвечает общим 404. Полный текст открывается в панели версии, отрывок списка ограничен 160 символами. Для ссылки, сохранённой операторской поставкой, хранитель может разрешить SHA-256 точного проверенного HTTPS-адреса в evidence_link_hashes этой поставки. Деталь выдаёт только такой адрес с обычным доменным именем и безопасным путём. В остальных случаях source_url равен null. Ссылка открывается вручную без referrer. Подтверждённых смещений цитат в этом профиле пока нет, evidence_span равен null.

## Ручная приёмка

Собрать кабинет по [регламенту PR-13](browser-cabinet.md) и выполнить `bash operational/test-postgres.sh -s` в отдельном worktree. Нативный сценарий запускает обе службы и PostgreSQL на одноразовых данных. Для скриншотов и видео задать приватный каталог `RS_TEST_BROWSER_OUT`.

1. Открыть позицию 1 в A, затем в B. Проверить разные тексты, общий identity_id и разные version_id. У r2/r3 в обоих снимках остаётся та же версия.
2. В B выбрать позицию 5, открыть панель, вернуться назад. В адресе остаётся фильтр, в панели явно отсутствует внешний ID.
3. В JSON открыть позицию 1 с конфликтующим ID. Список принятых позиций пуст, карантин доступен в журнале поставки.
4. На длинной синтетической выборке открыть вторую страницу и вернуться к позиции 1. В Firefox и Chromium разметка отображается обычным текстом, полная запись доступна при ширине 320 пикселей. Точный фрагмент помечен как неразмеченный.
5. Повторить доступ после смены роли, отзыва допуска, удаления и восстановления прежнего dump. Ранее выданная сессия недействительна на восстановленной базе.

Ревизия 0008 forward-only. Для отката используется новая независимая копия PostgreSQL и объектов с актуальными свидетельствами доступа и удалений. [Процедура восстановления](retention-operations.md)
