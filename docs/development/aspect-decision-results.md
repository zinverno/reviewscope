# Решения о жалобах во всём снимке

**QUALITY_GATE_NOT_MET · SYNTHETIC_EVIDENCE_ONLY.** На 66 новых авторских отзывах парная модель, выбранная на калибровке, нашла 24 из 32 жалоб с известной разметкой. Из 46 её положительных решений на парах с известной позицией 22 оказались ошибками. Все три модели обработали каждый из 66 текстов для каждого из шести аспектов. В кабинете переносимый лексический профиль доступен для экспериментального просмотра и ручной проверки.

Пороги margin во всех трёх случаях равны 0 по выбору на calibration. Модель всё ещё может выдать выученные классы неясности. Исход фиксируется до открытия test. Для gate требовались precision ≥0,85, recall ≥0,80 и определённый охват ≥0,80 как в целом, так и по очереди и готовой выдаче, с дополнительными проверками отрицаний, mixed и длинного текста. Независимых реальных меток нет. Результат MiniLM с раздельным кодированием на test сохраняется как наблюдение, выбор по calibration остаётся прежним.

У лексического контроля на A не было ни одной предсказанной жалобы с известной полярностью. Пустой знаменатель precision передаётся как null. Support test составил 329 оценок вне темы, 26 жалоб, 6 mixed, 7 отрицаний, 7 положительных, 6 нейтральных, 7 неясных позиций при упоминании, 7 неопределённых по теме и 1 повреждённый случай с неизвестной меткой. Для бинарного исхода известны 381 из 396 пар. Неизвестные не образуют отрицательный класс. В end-to-end recall входят все 32 положительных gold, включая возможные отказы. В данном test у всех трёх моделей selective recall совпал с полной метрикой, поскольку ни один из известных положительных исходов не получил решение abstain. Два длинных положительных наблюдения недостаточны для вывода о качестве на длинных реальных отзывах.

Для сравнения с поиском на том же test, запросом служила точная формулировка каждого аспекта. PR-19 hybrid MiniLM охватил 13/32 известных жалоб среди первых 10 отзывов на аспект и 31/32 среди первых 50. PR-21 переставляет тот же пул. Если сохранить решения парного классификатора только внутри этого пула, результат составляет 10/32 и 23/32. Полный проход дал 24/32. Числа 13 и 31 задают верхнюю границу для проверки кандидатов идеальным классификатором в данном эксперименте.

## Ошибки, исходные данные и проверка

Например, для A парная модель назвала жалобой «Не правда, что мы толкались перед заказом: к девушке с блокнотом подошли первыми» (test-004). Фразу «Два поезда ушло с соседней платформы, прежде чем продавец вообще начал меня слушать» (test-001) она отнесла к исходам вне темы. Для B в test-060 она пропустила ожидание закрытого стакана рядом с похвалой кофе. Полный текст, точные размеченные полуинтервалы и идентификаторы пар есть в [фикстуре](../../tests/data/fixtures/decision_reviews_v1.jsonl). Все строки авторские.

До обучения зафиксированы 55 train, 42 calibration и 66 test, всего 163 разных текста и 978 явно размеченных пар. Каждая запись — отдельная написанная сцена. Применён меньший, чем ориентир 300–450, бюджет, чтобы сохранить ручную разметку всех шести аспектов и исходных участков текста. Семейства, ID и нормализованные тексты разделов не пересекаются; совпадений текста с PR-21 нет. Наибольшее посимвольное сходство SequenceMatcher между разделами после casefold и нормализации пробелов равно 0,5065. Один источник синтетики ограничивает независимость формулировок. Разметка содержит полные окна контекста и несколько аспектов в одном отзыве. Рейтинг, автор и время не входят в признаки. Новые определения и правки payload имеют статус неподдерживаемых до отдельной оценки.

Базовый коммит `8c0f431ed28c82948c79d5bf290dbd3f3b1a0547`. Freeze `c03a6400948e5980f79ac0b89298836cac5a8063`. Манифест обученных весов, пороги и выбор на calibration опубликованы до первого test в `044637cd4d4c95519582f90fbed02d4aa282ac71`. У каждого из шести точных определений свой линейный классификатор. Редкий класс, отсутствующий среди train примеров данного аспекта, этот классификатор предсказывать не может. Все модели используют C=3, L2, class_weight=balanced, lbfgs и seed 2201. Совместный вариант использует настоящий второй сегмент токенизатора с текстом отзыва и mean-pooling его контекстных векторов. Отдельный вариант использует нормированные эмбеддинги текста, произведение и абсолютную разность с представлением полей определения. Все исходные окна покрыты, при переполнении 128 токенов интервал рекурсивно делится. Лексический профиль использует все символьные n-граммы 3–5 в окне, хеширование в 1024 признака и L2-нормализацию. Величина margin — разница двух наибольших логитов. Калибровка вероятностей не проводилась. ## Ресурсы и воспроизведение

AMD Ryzen 5 5500U, 12 доступных логических CPU, один Torch/BLAS thread. Шесть аспектов, одинаковые 396 выходов. Первые замеры включали одновременные локальные проверки; wall зависит от нагрузки. Значения начинаются после импорта Python-модулей процесса. Prepare включает сверку frozen данных, SHA и локальную загрузку весов. Peak RSS дан целиком для исследовательского процесса. Время fit в таблице относится только к обучению голов; оценка test использует уже обученные головы, с новой загрузкой encoder.

| Метод | Fit голов, с | Prepare test, с | Полный test wall / CPU, с | Peak RSS test, МиБ |
|---|---:|---:|---:|---:|
| Лексический | 0,076 | 0,012 | 0,079 / 0,072 | 237 |
| MiniLM отдельно | 0,405 | 7,521 | 11,922 / 9,787 | 1505 |
| MiniLM совместно | 0,687 | 15,377 | 39,530 / 28,619 | 1498 |

Для выбранного при калибровке исследовательского pair-профиля первый проход разнообразных 10 000 текстов PR-21 завершился RESOURCE_LIMIT по wall через 120,28 с. На последнем завершённом batch обработаны 640/10 000, 723 окна, 49 715 токенов. Пиковый sampled RSS child 921 316 КиБ. Частичный результат не опубликован. Контроль кабинета с лексическими весами и производительность хранения измеряются отдельно. Это синтетические замеры, их переносимость на клиентские данные неизвестна. Внешних вызовов inference и платных запросов не было.

Для повтора используется изолированная сеть только с loopback, уже подготовленный локальный cache PR-21, HF_HUB_OFFLINE=1, TRANSFORMERS_OFFLINE=1, HF_HUB_DISABLE_TELEMETRY=1, OMP_NUM_THREADS=1, OPENBLAS_NUM_THREADS=1, TOKENIZERS_PARALLELISM=false и PYTHONPATH с src и корнем репозитория. Нужны точные версии из reference runtime PR-21, numpy 2.5.3 и scikit-learn 1.9.1 для побайтной проверки. MiniLM `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, Apache-2.0, ревизия `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, model.safetensors 470 641 600 байт. Сверяются все файлы с существующим [манифестом SHA](rerank-evidence/minilm-cache.json); затем CPU FP32, локальный fast tokenizer и safe tensors. В веса линейных голов вошла только описанная синтетика. Сериализация NPZ без pickle.

```bash
sha256sum -c tests/data/fixtures/decision-freeze.sha256
sha256sum -c tests/data/fixtures/rerank-freeze.sha256
first=$(mktemp -d)
repeat=$(mktemp -d)
for m in lexical minilm pair; do
  python -m scripts.benchmark_aspect_decisions "$first" fit "$m" || exit 1
done
python -m scripts.benchmark_aspect_decisions "$first" select
cmp "$first/selection.json" docs/development/aspect-decision-evidence/selection.json
cp "$first/"*.npz "$first/selection.json" "$repeat/"
for dir in "$first" "$repeat"; do
  for m in lexical minilm pair; do
    python -m scripts.benchmark_aspect_decisions "$dir" test "$m" || exit 1
  done
done
python -m scripts.decision_retrieval_control "$first" retrieve
python -m scripts.decision_retrieval_control "$first" rerank
report=$(mktemp -d)
cp "$first/selection.json" "$report/"
python -m scripts.report_aspect_decisions "$first" "$repeat" "$report"
python -m scripts.profile_aspect_decisions
```

В первой попытке запуска из песочницы сетевое пространство не удалось настроить (netlink operation not permitted); разрешённая изолированная команда завершила модельную оценку. Две попытки ресурсной/поисковой команды с неверным именем скрипта вернули ошибку аргументов до вычислений. Отдельный воспроизводимый контроль поиска выполнен с указанным выше модулем. Независимую оценку реальных отзывов допускает только будущий закрытый пакет с проверенным происхождением и полной матрицей judgments по протоколу PR-05. REAL_LABELS_NOT_AVAILABLE.
