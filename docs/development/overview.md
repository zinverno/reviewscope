# Обзор снимка и Discover

**NEEDS_OVERVIEW_UX_REVIEW · ANALYTICS_BLOCKED_FOR_CANONICAL**

В локальном кабинете на TLS 8001 ссылка «Обзор выбранного снимка» показывает результат штатного worker. Адрес сохраняет workspace, source, snapshot, run, фильтры и выбранную версию отзыва. При наличии run сервер читает только этот запуск внутри указанного снимка. Если запуск завершился ошибкой, владелец может открыть последнюю успешную сводку отдельной ссылкой.

## Канонические данные

GET `/api/v1/workspaces/{w}/snapshots/{k}/summary-metrics` принимает необязательные `run_id` и `source_id`. Действуют текущая сессия, membership, RLS и журнал удаления. Порт 8000 обслуживает свой прежний контракт. Миграция 0009 расширяет числовую проекцию результата PR-11 под существующим внешним ключом артефакта. Проверяются SHA артефакта, идентификаторы workspace, run, snapshot, source и batch. Из результата берутся только счётчики с допустимыми знаменателями и известными кодами. Границы периода берутся из сверенной поставки. Web-роль сохраняет прежние полномочия.

| Показатель | Знаменатель |
| --- | --- |
| Принятые позиции, карантин, точные повторы позиций, причины поставки | Все входные позиции |
| Пригодность и причины исключения из метрик | Принятые immutable версии |
| Распределение звёзд | Принятые версии с известной оценкой в заявленной шкале 1–5 |

Нулевой знаменатель показан как Н/Д с причиной. Неизвестный период и неизвестное покрытие сохраняются. После установки 0009 исторические проекции сохраняют прежние числа, поле context у них равно null. Новая проверка создаёт отдельный run с контекстом. Условия фильтра восстанавливаются при переходе к отдельной версии и обратно. Для подвыборки показывается только фактическое число разрешённых отзывов из панели доказательств. Отсутствующие агрегаты имеют состояние FILTER_NOT_COMPUTED. Полная выборка worker — принятые позиции конкретной поставки.

Канонический worker пока публикует только snapshot_integrity_and_summary_v1. Темы, сравнение периодов, аналитические подборки и выводы о жалобах для workspace остаются заблокированы.

## Упакованный публичный набор

Режим `/cabinet/?view=legacy` показывает только заранее рассчитанные данные из синтетического DuckDB с SHA-256 `85ca0756ca60f56c735360ab46632d8893287635e7fec1a28548f97dae5fcfe2`. `python scripts/build_cabinet_demo.py` открывает именно этот файл read-only, запрещает внешние обращения DuckDB и проверяет полный замороженный набор векторов. AnalysisEngine, Discover и keywords_by_rating формируют версионированный результат public-demo-overview-v1. Его идентификатор — SHA-256 канонической сериализации полей результата. Таблица Discover ранжирует точки по доле 1 ★ или 5 ★ среди оценённых записей. Группы тональности повторяют метод ядра: 4–5 ★ и 1–2 ★. Термины упорядочены по исходному весу ядра. При точном равенстве веса применяется алфавитный порядок Unicode по всему словарю до отбора первых N. Все весовые значения сохраняются. Например, пять терминов положительной группы p1 имеют одинаковый вес на границе десятки. Браузер использует готовый продукт сборки, вычисления модели в процессе запроса отсутствуют.

## Приёмка и откат

1. Собрать кабинет по [регламенту PR-13](browser-cabinet.md). В отдельном синтетическом кластере выполнить `bash operational/test-postgres.sh -s`. Для видео и скриншотов после входа можно задать `RS_TEST_BROWSER_OUT`.
2. Сравнить A (3/3), B (6/6) и JSON (6/12). На JSON открыть исключения, выбрать «Только с текстом», перейти к отзывам и вернуться. Сверить вкладку с прежним запуском после неуспешной проверки.
3. В публичном режиме выбрать p1 и p2, сверить цифры с `python -m pytest tests/test_cabinet_demo.py`. Поиск по реальным источникам и сравнение периодов на неизвестном покрытии остаются за пределами этой демонстрации.
4. Миграция forward-only. Для восстановления требуется отдельная копия PostgreSQL и объектов, актуальный deletion ledger и свидетельство доступа. [Восстановление](retention-operations.md)
