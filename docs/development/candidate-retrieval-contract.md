# Roadmap PR-19 · Поиск кандидатов на снимке

Кабинет принимает временную формулировку или текст примера и возвращает фрагменты из принятых версий выбранного снимка. Путь владельца или аналитика проходит через «Отзывы и доказательства» → «Поиск кандидатов по снимку» → «Фрагмент» → «Полный текст версии». Отрицание и сарказм тоже могут попасть в результат. Владелец оценивает смысл по контексту. Размер выдачи ограничивает число разных отзывов.

## Адрес фрагмента и индекс

Каноническая область включает workspace, source, batch, snapshot, SHA manifest и JSONL, объявленное покрытие. Сортировка корпуса по version ID, проверка manifest, списка snapshot_member, принятых позиций журнала и байтов каждого объекта предшествуют поиску. Авторский идентификатор не требуется. Версии с одинаковым текстом сохраняют разные места в рейтинге. Отсутствующие и пробельные тексты входят в число принятых. Публичный эксперимент привязывает каждую версию к SHA отдельного демонабора, месту, source_result и review ID из замороженного обзора.

`fragmentation-v1` обрабатывает исходную строку без нормализации. Граница предложения проходит после группы знаков конца предложения с закрывающей кавычкой или скобкой перед пробелом либо концом строки. Переносы, включая CRLF, тоже образуют границу. Внутренние точки URL и дроби сохраняются. Точка сокращения перед пробелом может разделить предложение. Предыдущее и следующее окна остаются в контексте. Для длинного предложения предел равен 240 code points. Разделитель выбирает последний пробел в окне, а для непрерывной строки использует жёсткую границу. При превышении 128 реальных токенов MiniLM окно уменьшается вдвое и проверяется повторно. Каждая непробельная позиция, включая хвост, входит хотя бы в один anchor. Межоконные пробелы остаются в цитируемом источнике.

Четыре смещения задают полуинтервалы Unicode code points. Поиск кодирует исходный `[start,end)`. Панель показывает `[context_start,context_end)` с выделением anchor. SHA-256 использует точные байты UTF-8. Адрес фрагмента хеширует область, версию, content SHA, text SHA, спецификацию сегментации, tokenizer ID и границы. SQL привязывает публикацию к run, запросу, версии и контрольной сумме и проверяет границы в оригинале. При чтении сервер заново проверяет права, bytes/SHA объекта брокера, scope, version, SHA текста и границы. Клиент повторяет проверку SHA и срез через `Array.from`, выводит текстовые узлы React. Ошибка закрывает деталь.

## Ранжирование и бюджеты

| Канал | Вход и порядок |
|---|---|
| Lexical | `char_wb` TF-IDF 3–5, sklearn defaults, float32, L2, точное скалярное произведение. Fit на полном выбранном корпусе. Нулевое лексическое совпадение даёт пустую выдачу. |
| Dense | Offline CPU MiniLM из PR-04, revision `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, 384D, длина 128 вместе со special tokens, проверенные конечные ненулевые векторы. Query и anchor используют общий encoder без prefix. Document, query_to_passage и text_to_text имеют отдельные role ID. |
| Hybrid | Каждый канал даёт до 50 разных версий и до двух фрагментов на версию. RRF суммирует `1 / (60 + исходный ранг в канале)` по совпадающим fragment ID. Сохраняются rank и cosine каждого канала. |

Ties разрешает возрастающий fragment ID. Review rank определяется первым фрагментом версии. Остальные отобранные фрагменты этих версий остаются в выдаче. В кабинете K от 1 до 10 distinct reviews, максимум 40 записей для двух каналов. В отчёте K до 50. Пустая выдача и недобор K имеют явные счётчики. Методы используют exact query-to-corpus без матрицы пар. Исторические frozen vectors не участвуют. Прежний benchmark сортирует ties по seed 42 и включает нулевые scores. Этот порядок воспроизведён для whole-review сравнения.

Лимиты ядра — 10 000 версий, 4 МиБ исходного текста, 60 000 фрагментов и 2 048 байт на запрос. При построении dense-индекса одинаковые точные входы кодируются один раз внутри конкретного процесса. Manifest содержит encoding contract с runtime, хеши состава и порядка, словаря и IDF, спецификацию fusion. Разница float32 между платформами может изменить порядок близких значений. При отсутствии weights/backend либо несовместимом контракте dense/hybrid возвращают явный статус и пустой результат. Пользователь может отдельно запустить lexical.

## Доступ, запуск и жизненный цикл

API работает в локальном TLS-кабинете. `POST /api/v1/workspaces/{w}/snapshots/{s}/candidates` принимает JSON с `source_id, idempotency_key, query, role, mode, k` при действующей сессии, Origin и CSRF. `GET` того же маршрута принимает `source_id`, опционально `run_id` и `fragment_id`. Последний возвращает evidence той же версии в транзакции чтения. Список сохранённых запусков доступен при открытии снимка. Статус и отмена используют прежние маршруты PR-11. Повтор POST с прежними параметрами возвращает тот же запуск, изменение параметра с тем же ключом даёт 409. Текст запроса передаётся только в теле. Кабинет хранит ключ повтора в памяти до успешного ответа.

Миграция `0012_candidate_search` добавляет закрытый JSONB-параметр к analysis_run и отдельный `candidate_allowed DEFAULT false` к browser_admission. Оператор включает обработку только после сверки workspace/source и SHA конкретного вымышленного файла, на который уже выдан evidence-допуск. Право на историю автора независимо. Изменение параметров запрещено. Runtime использует scoped functions и не читает колонку запроса и сырые версии. До передачи запроса драйверу проверяются стандартные настройки записи SQL bind parameters. Вне приложения оператор отвечает за закрытые SQL/OS-трассировки и файлы дампа.

`snapshot_candidate_search_v1` использует рабочую роль, lease, verify/summarize/publish, witness и проверку приватного корня из PR-11/12. После проверки входа отдельный CPU-процесс получает минимальную проекцию и запрос через анонимный pipe. Родитель продлевает lease, учитывает отмену, останавливает дочерний процесс при таймауте 120 секунд или измеренном пике выше 2 ГиБ; при гибели родителя действует Linux PDEATHSIG. Модель загружается offline. Векторы, текст фрагментов и индекс существуют в памяти. В artifact сохраняются только ограниченные metadata и SHA, до 65 536 байт. Диагностика времени и RSS идёт отдельно в числовое событие worker. При отзыве допуска публикация и чтение закрываются. Неудачная транзакция после fsync может оставить объект без ссылки; штатный повтор использует те же байты, а регламент retention отвечает за очистку.

Owner export передаёт исходные параметры и проверяемый объект в закрытый архив, пока допуск действует. Erase и восстановление используют существующую связь snapshot → run → artifact, текущий ledger и access seal, включая обновлённый grant. Экспорт требует оператора. Физическое исчезновение старых backup не доказано.

## Воспроизведение

```bash
python scripts/benchmark_retrieval.py --validate-only
python scripts/benchmark_retrieval.py --minilm
python scripts/benchmark_candidates.py --minilm --public > /tmp/candidate-synthetic.json
(cd prototypes/reviewscope-ui && npm ci && npm run build && npx playwright install chromium firefox)
RS_MEASURE_DENSE=1 bash operational/test-isolated.sh -s --tb=short
```

Последняя команда требует PostgreSQL, Linux namespace, openssl, certutil, Node и подготовленных Python extras. Она создаёт собственные сеть, TLS, роли, БД, объекты и witness, поднимает кабинет на его собственном loopback и завершает процессы. Без offline-весов базовое сравнение lexical доступно командой `python scripts/benchmark_candidates.py`. Модель берётся из подготовленного локального кэша точной ревизии. Автоматической загрузки нет.

Для сравнения review-level Recall@K числитель равен числу различных найденных версий grade 2, знаменатель — всем версиям grade 2 в полностью размеченном корпусе. При неизвестной паре или нулевом знаменателе метрика null. MRR@K использует первый grade 2, nDCG — grades 0/1/2. Второй показатель проверяет, входит ли вся заранее размеченная цитата в первый отобранный anchor версии и весь требуемый контекст в показанное окно. Несколько цитат одной версии имеют отдельные знаменатели. Для whole-review проверяется доступный при раскрытии полный текст; усечение входа encoder измеряется отдельно. Полная матрица и примеры ошибок приведены в [протоколе измерения](candidate-retrieval-results.md).

`REAL_LABELS_NOT_AVAILABLE` · `BLOCKED_REAL_SOURCE` · `BLOCKED_CLIENT_PILOT` · `BACKUP_ERASURE_NOT_VERIFIED` · `OWNER_EXPORT_REQUIRES_OPERATOR`. Для принятой архитектуры PR-12–16 действует `TECHNICAL_ACCEPTED · UX_REJECTED`. Продуктовый редизайн отложен до завершения PR-33. `ANALYTICS_OUTPUT_SCALING_DEBT` остаётся для полных производных матриц и постоянных индексов. Их приёмке нужны staged chunks, проверяемый manifest, атомарная публикация и независимый purge/restore всех частей.
