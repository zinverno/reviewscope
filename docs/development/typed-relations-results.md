# Оценка классификации прямых пар

**RELATION_QUALITY_GATE_NOT_MET · INSUFFICIENT_EVIDENCE для near_copy · SYNTHETIC_EVIDENCE_ONLY.** Машинная классификация общей жалобы и противоположных позиций оказалась недостаточно точной и пропускает большинство положительных пар. В кабинете эти типы выводятся только по двум событиям выбранной ручной редакции. Технический oracle проверяет происхождение и бухгалтерию этого вывода; независимого pair-level precision для него нет.

### Корпус и знаменатели

90 авторских русскоязычных версий, три непересекающихся блока по 30, 435 пар на блок. Для каждой пары заданы текстовая ось и два отдельных определения A/B. Семейства и исходные тексты разделены до построения пар. В test для каждого аспекта 406 размеченных пар и 29 с неизвестной меткой. Для текстовой оси известны все 435. Общий пул содержит 90/435 пар (20,7%), в нём 87 пар с известным исходом по каждому аспекту. 345 пар вне пула остаются неоценёнными и учитываются при расчёте end-to-end recall. Одни и те же отзывы участвуют в нескольких парах. Корпус использует уже известные определения.

Freeze `dfc3b4da668244dc65c6cc5f405edf7ecadaae97`. Выбор по calibration и хеши коэффициентов зафиксированы в `6492e85034d54c08e061396935eafa1370f3c33c`. По A при равном F1 целевых классов остались правила, по B выбрана симметричная линейная голова. Рейтинг, идентификаторы, gold spans и человеческие исправления не входили в признаки. Для переноса на новые аспекты измерений нет.

В ячейке — найденные положительные пары / все положительные пары. RapidFuzz и cosine характеризуют разные способы отбора. У соседей хранится направление и ранг каждого попадания до симметричного объединения.

### Классификация на фиксированном пуле и сквозной результат

Полные confusion matrices, micro/macro F1, неизвестные исходы и срезы mixed, отрицаний, одинаковых текстов и длинного хвоста лежат в сырых результатах.

Три правильно найденные близкие копии при восьми положительных примерах недостаточны для заявленного минимума 10. У выбранной головы B две ложные общие жалобы на парах с gold no_relation. Выбранные методы ни разу не поменяли местами gold opposite и same complaint, однако низкая полнота ограничивает это наблюдение. Для точного совпадения доступен фильтр по самому проверяемому равенству. Одна авторская пара не даёт оснований для вывода о происхождении текста.

В 2 700 межблочных сравнениях нормализованных дубликатов нет; максимальный RapidFuzz ratio 0,578. В сравнении всех 90 версий с прежними PR-05/19/21/22 отсутствуют точные совпадения и пары с ratio ≥0,85. Максимум 0,619 на PR-22. Это проверка утечки формулировок, не тест рыночного качества.

### Ресурсы и проверка предыдущих этапов

Измерения сделаны на синтетике. В действительном импорте A принято 3/3, B 6/6, в проблемном JSON 6/12 (пять в карантине и одна подтверждённая повторная позиция). Все шесть принятых текстов проблемного JSON пусты для графа. У A сохранено ноль прямых пар, у B три по общим словам. Проверка конкретных текстов, двух позиций и замороженных событий использует отдельный контролируемый снимок.

Портативный lexical producer считал по фактически принятым версиям тех же снимков. При N≤128 он сравнивает все пары. На больших входах он сравнивает до двух следующих соседей в лексическом порядке и отдельно перечисляет exact только после комбинаторной проверки лимита. На публичном 1058/12 получено 114 кандидатов при 2 113 сравнениях. На разнообразном 10k — 19 234 кандидата при 19 997 сравнениях, 0,25 с в первом проходе и около 70 МиБ пикового RSS дочернего процесса. На 10k одинаковых текстов точный счёт 49 995 000 дал `PAIR_BUDGET_LIMIT` до перечисления. Малый онлайн-профиль отклоняет эти большие снимки до публикации. Dense top-K измерен только на размеченных блоках.

В PostgreSQL 18.6 опубликован 21 результат по 496 строк (10 416 рёбер). Последняя и первая страницы посещали до 496 строк своего результата в generic/custom plans, до и после ANALYZE с изменённой ценой чтения. Три HTTP-ответа заняли 7 163–11 059 байт. Экспорт составил 14 361 102 байта, 1,63 с. Подтверждение и purge заняли 1,14 с. Измерения зависят от машины. Браузерные проверки используют изолированный TLS, Chromium и Firefox, 320/390/1366/1920 CSS px и reduced motion. Физический телефон — NOT_VERIFIED.

### Повтор эксперимента

Требуются штатные numerical/embeddings зависимости, закреплённые локальные веса MiniLM и изолированный network namespace, в котором доступен только loopback. Обучение линейной головы идёт только на train. Скрипт отклоняет несовпадение контрольных сумм и весов перед оценкой. На зафиксированном выборе повторная оценка дала байтово одинаковые scores, ранги, интервалы, предсказания и метрики.

```sh
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
mkdir -p /tmp/relations-repeat
python -m scripts.benchmark_relations calibration /tmp/relations-repeat /tmp/relations-repeat/selection.json
python -m scripts.benchmark_relations test /tmp/relations-repeat /tmp/relations-repeat/selection.json
cmp /tmp/relations-repeat/test-pairs.jsonl.gz docs/development/typed-relation-evidence/test-pairs.jsonl.gz
python -m scripts.report_relations
```
