# PR-09 · Локальный предварительный разбор поставки

**NEEDS_IMPORT_CONTRACT_REVIEW · REAL_FORMAT_NOT_VERIFIED.** На двух синтетических поставках PR-02 приняты 3/3 и 6/6 записей. Разрешённых клиентских файлов получено 0. У пилота сохраняются **BLOCKED_REAL_SOURCE** и **BLOCKED_CLIENT_PILOT**. [Исходный пример A и B](pilot/data-contract.md) · [Статус пилота](pilot/status.md)

## Воспроизведение

Из корня checkout на Linux с Python 3.12+ и системной базой IANA выполните команду. Ключи `-IS` запускают изолированный Python без site-packages. Достаточно стандартной библиотеки.

```bash
f=tests/data/fixtures/import_preview
python -IS scripts/preview_import.py --format csv --input "$f/b.csv" \
  --mapping "$f/mapping.json" --passport "$f/b.passport.json" \
  --out-dir validation_data/private/import-preview
```

Для A замените `b.csv` и `b.passport.json` на соответствующие файлы A. Для JSON передайте `--format json` и паспорт без delimiter. Для получения одних счётчиков опустите `--out-dir`. Код выхода 0 означает, что доступен полный отчёт, в том числе когда все строки в карантине. При отказе код выхода 2, stderr содержит только JSON с фиксированным кодом и русским описанием. Некорректный файл не публикует частичный preview.

| Поставка | Вход | Приняты | Карантин | Подтверждённые повторы | Без автора | Без внешнего ID | Без даты / текста / звёзд | Предупреждения |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| A | 3 | 3 | 0 | 0 | 3 | 0 | 0 / 0 / 0 | 3 |
| B | 6 | 6 | 0 | 0 | 6 | 1 | 0 / 0 / 0 | 7 |

В A три `missing_reviewer`. В B шесть `missing_reviewer` и один `missing_review_id` в позиции 5. У сентябрьского r1 два разных текста в двух независимых preview. Оценка жалоб 1/3 и 2/3 в исходном примере остаётся ручной разметкой PR-02. CLI не анализирует жалобы.

В отдельном синтетическом JSON-тесте 12 входных элементов дают 6 принятых, 5 в карантине и 1 подтверждённый повтор. Три строки карантина делят один конфликтующий ID, одна позиция содержит не-объект, ещё одна — числовой ID. Две одинаковые анонимные строки приняты отдельно.

## Вход, mapping и паспорт

CSV содержит заголовок, разделитель из паспорта (запятая, точка с запятой, табуляция, вертикальная черта), удвоенные кавычки и переводы строк внутри кавычек. По умолчанию декодирование строгое UTF-8 с допустимым BOM. CP1251 требует явного `"encoding":"cp1251"`. JSON использует UTF-8 и допускает BOM. Формы документа — массив либо объект с единственным ключом `reviews` и значением-массивом. Все элементы массива получают позицию, в том числе числа и null. Внутри объекта строки значения должны быть скалярными. Повтор JSON-ключа на любой глубине делает весь документ неоднозначным.

Mapping — JSON вида `{"version":"example-1","fields":{"comment":"text","score":"rating","other":null}}`. Это точные имена столбцов с учётом регистра. Значение null явно исключает столбец из канонических данных. Пустые имена, повтор назначения, выражения вместо допустимой цели и неизвестные цели отклоняются. В CSV множество имён должно совпасть с профилем. В JSON поле может отсутствовать в отдельном объекте, но каждое заявленное имя должно встретиться хотя бы в одном объекте. Если вход состоит целиком из не-объектов, все позиции попадают в карантин. Лишний ключ отдельного объекта или лишняя ячейка строки CSV диагностируются по позиции. Формулы и похожий на код текст остаются строками.

Паспорт — JSON-объект. Допустимые ключи перечислены ниже. Незнакомый ключ даёт отказ. Для файла JSON с полями из примера mapping минимальный привязанный паспорт имеет вид `{"source":"synthetic","source_place_id":"p1","event_basis":"published","rating_scale":[1,5]}`.

| Свойство паспорта | Семантика |
| --- | --- |
| `source`, `source_place_id` | Непустые строки. Заполняют отсутствующую привязку файла. Расхождение с непустым полем строки отправляет её в карантин. Обе привязки обязательны для принятой строки. |
| `encoding`, `delimiter` | Кодировки utf-8, utf-8-sig, для CSV также cp1251. Разделитель обязателен в CSV. |
| `event_basis`, `timezone`, `local_date` | Смысл даты published/submitted/edited/unknown, по умолчанию unknown. Необязательное имя IANA относится к локальному времени. Системные псевдонимы localtime и posixrules и служебные деревья posix/right исключены. Опция DD.MM.YYYY дополнительно разрешает ровно эту форму календарной даты. |
| `rating_scale` | Две целые границы по возрастанию, включительно. Только заявленная [1,5] с целыми значениями допускает прямое использование звёзд. Другие шкалы сохраняются для будущего согласования. |
| `observed_at` | Необязательный момент наблюдения всей поставки с явным смещением. Mapping одноимённого поля означает проверку значения строки против паспорта по UTC. Без паспортного момента такое назначение отклоняется. |

## Каноническая строка и доказательство происхождения

Python-вход `reviewscope.import_preview.preview(data, fmt, mapping, passport)` принимает исходные байты и возвращает `ImportPreview` с типизированными `CanonicalRow`, `EventTime`, `MappingProfile`, `Passport` и `ImportSummary`. Приватный JSON содержит объект `delivery` с паспортом, профилем, агрегатами и словарём сообщений, затем массив `rows` в порядке поставки.

| Поле | Канонический смысл |
| --- | --- |
| `source_position`, `field_provenance` | Позиция с 1 среди логических записей, без заголовка CSV. Перенос строки в кавычках входит в одну запись. Пара (file_sha256, позиция) при данном формате и профиле адресует оригинал, включая карантин. Для присутствующего поля указывается `field:<точное имя>`, для привязки из паспорта — `passport:<ключ>`. Отсутствующее поле JSON отличается от явно заданного null по provenance. |
| `source`, `source_place_id`, `source_review_id`, `reviewer_id` | ID принимаются строками, включая ведущие нули и значения длиннее машинного целого. Пустой или пробельный ID становится null. Числовой JSON ID получает диагностику типа. Отсутствие внешнего ID оставляет временную ссылку на позицию. У анонимного отзыва отсутствует авторская группа. |

| `rating_raw`, `rating_1_to_5` | Сохраняются исходная строка или точная лексема JSON-числа, заданная паспортом шкала и допустимые звёзды либо null. Исходный тип проверяется по позиции в файле. Некорректный скаляр имеет диагностику. Проверка числа работает в десятичной арифметике без округления. |

Дата без времени остаётся календарной. Местное время без смещения разрешается в UTC только при документированном поясе, когда обратное преобразование даёт ровно один момент. При DST gap/fold сохраняется исходное местное время. Для воспроизведения локального времени используйте ту же версию системной базы правил IANA. Смысл edited сохраняется даже при точном timestamp. Неверная дата, отсутствие автора или оценки оставляют остальные виды анализа доступными.

## Счётчики и карантин

Для успешно прочитанного файла перебор создаёт ровно один элемент результата на каждую логическую запись. Группировка внутри одной поставки использует (source, source_place_id, source_review_id) только при наличии всех трёх частей. Сравниваются все исходные поля, включая игнорируемые и лишние ячейки. У JSON порядок ключей несущественен, типы и лексемы чисел различимы. Разные исходные данные отправляют **всю** группу в карантин с позицией отличающейся записи. Если идентичность подтверждена, все данные равны и записи пригодны, первая принимается, каждая последующая ссылается на неё как confirmed_duplicate. Равенство текста у разных ID и равенство двух строк без ID сохраняют обе позиции.

Статус каждой позиции принадлежит ровно одному из трёх непересекающихся множеств. Смена решения внутри группы сохраняет количество позиций. Поэтому `total_input_rows = accepted + quarantined + confirmed_duplicates`. Проверка выполняется при построении сводки. Отказ целого файла отдельно возвращает ошибку без итоговых счётчиков.

`warning_count` суммирует вхождения предупреждений по всем позициям, включая повторы и карантин. `reason_counts` учитывает коды решений и предупреждений по всем позициям. Число конфликтующих **строк** равно `reason_counts.get("conflicting_id", 0)`. Показатели `missing_author_count`, `missing_review_id_count`, `missing_date_count`, `missing_rating_count`, `missing_text_count` и `rating_excluded_count` считаются только среди принятых. Отсутствующий либо неразрешённый для сбора ID даёт null. Отсутствующая дата и некорректная дата имеют разные коды. В rating_excluded_count входят все принятые строки без допустимых звёзд.

| Конфигурация и схема | invalid_format, invalid_mapping, conflicting_mapping, invalid_passport, unknown_column, unexpected_column (для заголовка целиком, для JSON-объекта по позиции) |
| Структура и привязка строки | invalid_json_item, invalid_field_type, row_width, missing_source, missing_place, binding_mismatch, observation_mismatch |

## Ресурсы и приватность

Предел входного файла 4 MiB, каждого конфигурационного файла 32 KiB, 10 000 записей, 64 столбца, 16 384 символа в поле, глубина JSON 8 контейнеров. Дополнительный общий предел JSON — 240 000 структурных разделителей и скобок вне строк. Он ограничивает суммарную аллокацию множества коротких контейнеров. Проверка размера открытого обычного файла и ограниченное чтение предшествуют декодированию. Структурный проход JSON предшествует построению объектов. CSV разбирается по логическим строкам. Вход ограничен и может находиться в памяти целиком. Пустой файл отклоняется. XLSX, ZIP, загрузки по URL и создание задач анализа отсутствуют.

На Linux, Ryzen 5 5500U, доступная системе физическая память 7 429 012 KiB, Python 3.14.7, каждый отдельный процесс получил предел адресного пространства 192 MiB. Оба синтетических файла занимали ровно 4 194 304 байта, содержали 10 000 разных ID и дали 10 000 принятых, 0 в карантине, 0 дублей и 30 000 предупреждений. Время ниже охватывает разбор и сводку. Пиковый RSS охватывает весь процесс, включая генерацию. Запись приватного JSON в этот замер не входит.

| Формат | Время, с | Пиковый RSS, KiB |
| --- | ---: | ---: |
| CSV | 0.227 | 63 980 |
| JSON | 0.337 | 48 276 |

Лимиты зафиксированы для этого локального профиля. Измерение характеризует указанные два файла. Повторите `python -IS tests/measure_import_preview.py csv` и аналогичную команду с `json` для другого компьютера.

CLI принимает пути от доверенного локального оператора. В stdout попадают версия процедуры, статус проверки, счётчики, фиксированные коды и SHA-256. Fingerprint — SHA-256 строки из версии процедуры, формата и трёх SHA-256 (байты входа, mapping, паспорта), соединённых вертикальной чертой. Он воспроизводит конфигурацию обработки. Две независимо полученные одинаковые поставки могут иметь один fingerprint. Время запуска в ключ не входит.

Оператор хранит исходные байты, mapping и паспорт в закрытом месте на разрешённый срок. Скрипт записывает детализацию только при явном выборе каталога под игнорируемым Git деревом `validation_data/private` данного checkout. Каталог принадлежит текущему UID и закрыт для группы и остальных. Промежуточный файл и опубликованный по fingerprint файл имеют режим 0600. Готовый файл появляется атомарно. Повтор принимает уже существующий побайтово равный файл. Расхождение оставляет прежний файл на месте. Символьные ссылки внутри пути вывода отклоняются. В CI достаточно синтетики и stdout, приватные JSON не прикрепляются.
