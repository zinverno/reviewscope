# Что обнаружил профиль PR-25 на синтетических отзывах

**TOPIC_QUALITY_GATE_NOT_MET · SYNTHETIC_EVIDENCE_ONLY.** Из 21 пары, которую объединил профиль, 10 описывали одну размеченную проблему. Из 37 известных однородных пар профиль нашёл 10. Результат подходит для просмотра гипотез по оригиналам. Частота жалоб и появление проблемы в бизнесе остаются неизвестными.

## Данные и единица оценки

Авторский [TSV](../../tests/fixtures/topic-discovery.tsv) и [протокол](topic-discovery-contract.md) зафиксированы до первого прогона в коммите `48db690be25d77e9023ef51357c550c78a172041`. SHA-256 TSV — `9cf883d1998ca03525d9738de897a5e459f7d474087a57ccdbaf4869440334fd`. Это 6 dev, 5 history и 28 holdout-сцен. Отдельные технические входы проверяют повторы, длинные тексты и смену снимка. Семейства формулировок и состав видны в TSV. Случайной инициализации нет. Семантический clustering — NOT_RUN: новый алгоритм и его правило выбора не фиксировались до открытия holdout. Ранее испытанные MiniLM и pair решают другие задачи.

Четыре кандидата реального профиля PostgreSQL, 28/28 принятых, пригодных, выбранных и уникальных отзывов. В группы вошли 15/28, в шум — 13/28. Пропущено вычислением 0, исключено при выборе 0. Три строки mixed/unknown исключены из парной метрики. На 25 оставшихся строках 300 пар: TP 10, FP 11, FN 27, TN 252. Precision 47,6%, recall 27,0%, F1 34,5%. Минимум по протоколу 80% и 60%. Среди назначенных однозначных строк purity составила 10/15. Группы из трёх разных текстов найдены для 2/4 тем с достаточной поддержкой. Общая лексика разделила похожие по смыслу жалобы и объединила разные.

| Авторская метка | Верно объединённые / все однородные пары |
|---|---:|
| Очередь до оформления | 0/10 |
| Ожидание готового заказа | 3/10 |
| Приготовление | 1/6 |
| Протечка стакана | 6/10 |
| Доступность меню | 0/1, поддержка 2, INSUFFICIENT_EVIDENCE |

Слово «пока» объединило разные этапы ожидания. Есть одна ложная пара очереди с выдачей. Похвала попала в группу выдачи, отрицание — в группу с жалобой. Фраза «крышка стакана» объединила четыре текста о протечке, а описание протечки через шов осталось вне группы. Подлинность ссылок на исходники проверена по UTF-8 SHA и Unicode-диапазону. Это не независимая человеческая оценка репрезентативности.

В отдельном запуске реального кабинетного PR-22 все пять размеченных жалоб на очередь получили not_mentioned. Режим по одному определению позволяет проверить эти пропуски. В полностью размеченной ранней поставке из пяти версий сюжета о протечке нет, поиск вернул 0/5 совпадений. В другом более раннем снимке нашлась иначе сформулированная жалоба, одно совпадение из двух просмотренных. Проверяющий открыл её точную версию и подтвердил аналогию. Поиск с последующим чтением квитанции занял около 0,11 с в обоих случаях. Перекрытие периодов и несовместимость профиля вернули HISTORY_NOT_COMPARABLE, частичная история сохранила отдельную квитанцию.

## Нагрузка и воспроизведение

Измерения на изолированном PostgreSQL 18.6, Linux x86_64. Использовались принятые версии реального импортера, broker и SQL producer. Числа времени и RSS относятся к отдельным проходам. Успехом публикации считается завершённый commit.

| Синтетический вход | Принятые / вход | Результат |
|---|---:|---|
| A | 3/3 | 3 уникальных, 0 в группах, 3 в шуме |
| B | 6/6 | 6 уникальных, 3 в группе, 3 в шуме |
| Problematic JSON | 6/12 | 5 quarantine, 1 подтверждённый дубль, 6 blank, выбрано 0 |
| 256 разных текстов + 256 копий | 512/512 | 64 группы, крупнейшая 260 версий из 4 разных текстов. В группах 512, шум 0 |
| Публичный demo | 1058/1058 | HTTP 413. Отдельный offline SQL обработал 1058 за 0,51 с, CPU 0,52 с, PG HWM 59 968 КиБ. 1033 уникальных, 157 кандидатов, 494 назначенных, 564 в шуме |
| 4 МиБ, разнообразные | 10 000/10 000 | HTTP 413 за 0,027 с, ответ 65 байт, обработано 0. Отдельный SQL остановлен на projection через 10,01 с, CPU 9,96 с, PG HWM 64 568 КиБ |
| 4 МиБ, повторы | 10 000/10 000 | HTTP 413 примерно за 0,03 с, 65 байт, обработано 0. Отдельный SQL достиг лимита 10 с. Итоговые кластеры, шум и число пройденных строк при прерывании неизвестны |

Для нагрузки 512 версий публикация и commit заняли 0,145 с. Размер manifest в измерительной JSON-сериализации — 1213 байт. Страницы 0/0/250 потребовали 8267/8267/4609 байт, 38/35/35 мс. Пик backend измерения чтения — 38 332 КиБ, родительского pytest — 298 676 КиБ. Размер плотной матрицы и внешнего staging — 0. Временные отношения и разреженные признаки создаёт PostgreSQL; точный объём внутреннего словаря и пиковая память одного HTTP-запроса отдельно не измерялись. Нормальное ограничение SQL 10 с осталось включённым.

В первом полном stress-прогоне generic plan до ANALYZE повторил индексный обход review_version 512 раз (131 328 посещений). Квитанция теперь отдельно сверяет отсортированный состав snapshot_member и читает версии по массиву sealed UUID. При повторе до/после ANALYZE и с generic/custom планом максимум составил 512 посещённых строк на измеренный узел. Для review_version получено 512 строк × 1, shared hits 1572/509/507/35. Измерены catalog, page и откатываемое действие. Код 413 на большом снимке и SQL timeout учитываются как ресурсные отказы.
