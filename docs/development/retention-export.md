# Manifest собственного экспорта

ZIP `owner-export-1` формируется по текущей owner-заявке и полномочиям под RLS. Внутри — `manifest.json`, UTF-8 JSON Lines в `rows/` и исходные байты по `objects/<sha256>`. ZIP использует фиксированную дату членов, порядок таблиц, порядок первичных ключей и лексикографический порядок объектов. Одинаковая заявка и зафиксированная выборка дают воспроизводимое содержимое; новая заявка получает новый идентификатор. Максимум 256 МиБ содержимого, отдельный импорт — 4 МиБ и 10 000 позиций. Чтение файлов блоками по 64 КиБ, таблиц серверным курсором. Архив передаётся проверенному получателю атомарным созданием нового файла без перезаписи.

| Поле | Значение |
| --- | --- |
| version, request_id | Версия manifest и идентичность выдачи |
| selection | UUID workspace, вид scope, UUID цели |
| references | UUID источника, UUID записи-владельца, роль файла, SHA; один физический объект может иметь несколько записей |
| entries | Имя члена ZIP, размер в байтах и SHA-256 его точного содержимого |
| omitted | Закрытые классы, внешние загрузки, отсутствующие ML-хранилища; для старых квитанций явное ограничение позиционного журнала |
| Ответ CLI | SHA-256 всего ZIP, SHA-256 manifest, размер и переход в custody получателя |

Идентичности, версии, происхождение полей, входные позиции и их статусы восстанавливаются из source, import_batch, import_row и review_version. Покрытие и неизвестное время остаются в исходном виде. Четыре входа канонической поставки и её JSON Lines доступны побайтово; manifest снимка, состав и проекция сверяются с PostgreSQL. Для артефакта сохранена связь через run и snapshot. Сессии, парольные данные, lease-токены, SQL-логины, приватные пути и содержимое диагностики не входят в ZIP. Персональные данные собственных разрешённых строк входят в приватную выдачу. HTTP возвращает только metadata с no-store.
