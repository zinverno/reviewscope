# PR-26 · Ручная проверка следующей поставки

## Решение до реализации

База — squash #29 `f3ace19ab44424e5023c6dcd46ed81f16ea40428`, дерево `f1f098f5e1808d75aca730ac7f477315333aa96b`. Профиль выбирает все `accepted_in_delivery` одного синтетического источника. Оператор допускает каждый checksum отдельно. Запуск вручную. Критерий будущего события хранится как минимальное количество упоминаний при заданном минимальном N_eligible, machine, версия 1. Состояние критерия — NOT_EVALUATED, QUALITY_GATE_NOT_MET.

* Монитор привязан к workspace/project/source, редакция — к точному UUID и digest определения PR-20. CAS по текущей редакции. Exact manual payload из шести поддержанных PR-22, lexical CPU и calibrated-v1. Иные определения можно сохранить. Архив закрывает новые команды, уже принятый запуск может завершиться при живых правах.
* Ключ наблюдения — принятая позиция PR-10. Для стабильной identity сравниваются version_id между двумя выбранными снимками. Одинаковые идентификаторы отзывов в разных точках имеют разные identity. Новый UUID, включая изменение только даты или оценки, требует расчёта. Отсутствующий внешний ID даёт identity, ограниченную batch/position. Повторы и карантин входят только в N_input.
* Отсутствие стабильной identity в target даёт not_observed_in_target при любом coverage. Предыдущая анонимная позиция учитывается отдельно. В coverage_passport имеются coverage, filters, mode, basis, covered_from/until, received_at. Нормализованный observed_at хранится в filters снимка. Проверяемого признака удаления в действующем договоре источника нет. SOURCE_REMOVAL_EVIDENCE_UNAVAILABLE. Физическое удаление по retention очищает данные обслуживаемой области.
* Привязать запуск к target, предыдущему успешному запуску той же редакции либо явному полному проходу, snapshot/manifest SHA и точным decision rows. Для reuse нужны успешная публикация, целые bytes и rows_sha256 родителя, тот же workspace/project/source/редакция/профиль/runtime/нормализация, тот же UUID и content/text SHA. PR-23 human revision относится к своему run. Отдельно считать blank, reused eligible, computed eligible. Независимый PR-22 на B служит контролем для каждой строки и агрегата.
* Короткая записывающая транзакция получает ledger gate, затем writer authority (workspace UPDATE через job_writer), затем проверяет project, source и точные допуски в стабильном порядке. Чтение каталога не подготавливает запись в той же транзакции. Worker берёт authority и lease до stage/publish, без удержания workspace во время inference. Перед расширением требуется проверить исходный порядок при одновременных импорте и enqueue.
* Отсутствие новой поставки определяется по регистрации snapshot. Отдельная поставка с теми же стабильными версиями — новое наблюдение. Проверка старого run не меняет последнюю успешную дату.

План предназначен для проверки реализации. Результаты фактических запусков перечисляются отдельно.
