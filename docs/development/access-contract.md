# PR-08 · Контракт локального доступа

Префикс `/api/v1`. Выделенный процесс на `127.0.0.1:8001`. Собственный `/openapi.json` описывает новые ресурсы. На порту 8000 сохраняются четыре прежних GET и их схемы. Локальный place ID имеет смысл внутри выбранного снимка.

Оператор создаёт аккаунт и первое членство закрытой командой в приватном терминале. Публичной регистрации и поиска людей по логину нет. Логин — 1–64 символа ASCII, нижний регистр, без крайних пробелов, первый символ буква или цифра, далее также допустимы точка, дефис и подчёркивание. Новый пароль — 12–256 символов. UUID аккаунта независим от автора отзыва. [Запуск и операторские команды](access-operations.md)

## Сессия

- `POST /session/login` принимает JSON только с полями `login` и `password`. Успех даёт 204 и cookie на восемь часов. Неверный логин и неверный пароль дают одинаковый 401. На процесс разрешены пять попыток за скользящие 60 секунд, успешные входят в счётчик. Шестая получает 429 до KDF. Перезапуск сбрасывает счётчик. Один клиент может временно занять весь лимит.
- `GET /session` возвращает собственный `principal_id` и страницу доступных workspace с текущими ролями. Без членств приходит пустой массив. `POST /session/logout` с пустым телом отзывает текущую сессию в БД и удаляет cookie, успех 204.
- Cookie host-only, HttpOnly, SameSite=Strict. На HTTPS имя `__Host-rs_session`, Path=/ и Secure. Явный режим `RS_ACCESS_HTTP_LOOPBACK=1` использует другое имя и принимает только HTTP с точным Host и loopback peer. Forwarded-заголовки штатный запуск игнорирует. Браузерные cookie разделяются по хосту и пути. Выделяйте доверенный локальный профиль и не запускайте недоверенные сервисы на том же имени хоста.
- Для всех изменяющих методов обязательны единственный `Origin` с точным origin сервиса и единственный `X-RS-CSRF: 1`. Пользовательский заголовок требует preflight у другого origin. Разрешающих CORS-заголовков нет. Проверка действует и на login/logout. Тело данных только JSON, до 4096 байтов. Query закрыт, кроме документированного offset. Повторные параметры отклоняются.

## Матрица HTTP

Числа относятся к корректному запросу с пройденной проверкой браузерного origin. В строках чтения «чужой» означает аутентифицированного человека без активного членства в указанной области. Роль всегда вычисляется заново по выбранному workspace.

| Маршрут | Owner | Analyst | Viewer | Чужой / inactive | Без сессии |
| --- | --- | --- | --- | --- | --- |
| GET /session, GET /workspaces | 200 свои | 200 свои | 200 свои | 200 только доступные | 401 |
| GET /workspaces/{w}/sources, /snapshots, /runs | 200 | 200 | 200 | 404 | 401 |
| GET тех же ресурсов с /{id} | 200 | 200 | 200 | 404 | 401 |
| PATCH /workspaces/{w}/members/{subject} | 204 | 403 | 403 | 404 | 401 |
| POST /session/logout | 204 | 204 | 204 | 204 | 401 |

В своём workspace неизвестный объект и объект другого workspace дают тот же JSON 404. PATCH меняет `role` и `state` уже связанного человека. Owner может активировать, отозвать и изменить роль другого участника, себя изменить нельзя (403). Ещё не связанный субъект даёт 404 независимо от существования глобального аккаунта. Новые связи создаёт доверенный оператор после проверки личности. Каталог пользователей между workspace закрыт.

Списки сортируются по UUID по возрастанию. Page size — 50, `offset` от 0 до 2147483647, по умолчанию 0. Страница за концом пуста. Workspace возвращает id/name/state/role. Source — id/kind, snapshot — id/source_id/created_at, run — id/snapshot_id/status. В ответах отсутствуют сырые отзывы, JSON источника, пути объектов, хэши, манифесты и идентификаторы чужих объектов.

| Действие authorization service | Owner | Analyst | Viewer | Нет активного членства |
| --- | --- | --- | --- | --- |
| Чтение | Да | Да | Да | Нет |
| Изменение членств | Да | Нет | Нет | Нет |
| Регистрация поставки, запуск анализа | Да | Да | Нет | Нет |
| Политика хранения и удаления | Да | Нет | Нет | Нет |
| Неизвестное действие | Нет | Нет | Нет | Нет |

Последние команды поставки, анализа и хранения представлены только правилами доступа. HTTP-запуск работ и удаление данных отсутствуют.

## Отказы и диагностика

Сервер генерирует `X-Request-ID`, добавляет `Cache-Control: no-store`. `X-Analysis-Execution-ID` возникает только при реальном вызове аналитического ядра в прежнем API. Сервер пишет JSON события с шаблоном маршрута, временем, статусом, кодом ошибки и серверными ID. UUID из URL, query, cookie, логин, SQL, текст исключения и тело запроса исключены из полей события.

Тело ошибки содержит только `error`. Коды — 400 invalid_host, 401 unauthenticated, 403 forbidden, 404 not_found, 405 method_not_allowed, 413 request_too_large, 422 invalid_request, 429 rate_limited, 500 internal_error, 503 access_unavailable. 503 возникает при непригодной конфигурации ключа, подключении, ревизии, профиле роли или ошибке запроса к схеме. Доступ закрыт до исправления причины. Открытая синтетика живёт в другом процессе.

Исторические статусы **BLOCKED_REAL_SOURCE**, **BLOCKED_CLIENT_PILOT**. Статус PR **NEEDS_AUTHZ_REVIEW**.
